### 2.1 Spring Modulith 落地设计（裁决 1 附带设计，PR-1 执行依据）

- **依赖与版本**：`spring-modulith-bom` **1.4.x（当前 1.4.13）** 父 POM 锁定（BOM 外依赖，禁漂移）；引入 `spring-modulith-starter-jdbc`（事件持久化走 JDBC 注册表，非 JPA——事件日志表与领域模型解耦）+ `spring-modulith-test`（边界校验与事件发布测试）。
- **事件日志表建表**：**Flyway 迁移承载（官方 event_publication 表结构，integration 号段 V6+ 登记）**，`spring.modulith.events.jdbc.schema-initialization.enabled=false`。偏差申报：用户参考配置为 `enabled=true` 框架自动建表，与宪法 A.4.1「Schema 唯一来源=Flyway、禁自动 DDL」红线冲突，且 `--scale backend=2` 多实例并发自动建表存在竞态——按修宪流程裁决为 Flyway 建表（单一代码源 + 实例间安全），若用户改判框架自动建表须同步修宪豁免。
- **重启重发关闭**：`spring.modulith.republish-outstanding-events-on-restart=false`（多实例下与其他在处理实例产生重复投递，仅单实例安全）。
- **重试与清理（EventOpsJob，编程式 API + 定时任务）**：①每分钟 `incomplete.resubmitIncompletePublicationsOlderThan(Duration.ofMinutes(5))`（重试卡住超 5 分钟的事件，给正常处理留窗口）；②每小时 `completed.deleteCompletedPublicationsOlderThan(Duration.ofDays(7))`（防事件日志表膨胀）。**两个任务必须挂 ShedLock**（宪法 A.5-14 多实例定时任务强制），锁表放公共 schema。
- **模块边界守护（CI 强制）**：JUnit `ApplicationModules.of(Application.class).verify()` 进 fuyun-app 测试套（纳入既有 verify 门禁）；与 ArchUnit 1.5.0 并存分工——Modulith 管模块级边界（slices 互斥/依赖方向），ArchUnit 管自定义分层规则；CI 输出 PlantUML/C4 模块依赖图（Modulith Documenter）作为架构评审依据。
- **监听器执行模型**：跨模块监听一律 `@ApplicationModuleListener`（等价 @Async + REQUIRES_NEW + after-commit——独立事务异步执行，不拖长业务事务、监听器失败不回滚业务）；**发布方必须在 Spring 事务代理内**（否则事件暂存后等不到提交信号，表现为事件卡住不投递——写入编码规范并在 PR 审核项核对）。
- **与既有 fy.topic RabbitMQ 总线的边界（PR-1 设计评审定稿）**：Modulith 事件发布注册表承载 **in-JVM 可靠投递**（替代宪法 B.3-3 原自建"事务后事件表+定时重投"形态）；跨实例广播/外部系统投递仍走 RabbitMQ 领域事件总线，`@Externalized` 桥接范围随 PR-1 设计评审定稿后再修宪补充；既有 `fy.delay` 延迟消息与 M20 治理构件不动。
