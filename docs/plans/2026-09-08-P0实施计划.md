## 0. 执行前必读（新会话第一步）

1. 通读根 `AGENTS.md`（定位层）→ 按路由通读 `backend/AGENTS.md` 与 `web/AGENTS.md`（宪法，写代码前必读）。
2. 版本一律取自 `docs/language/2026-09-07-技术栈选型.md` 定稿表 + backend/web 宪法 C.2（含 MyBatis-Plus 3.5.17、jacoco 0.8.15 须父 POM 显式锁定等裁决），禁止引入表外依赖；新依赖先在 PR 描述中申报理由。
3. **流程红线**：main 分支保护已生效（直推被拒）——一切变更：feature 分支 → `gh pr create` → 五项检查全绿（`backend / verify`、`frontend / verify`、`images`、`commitlint`、`hygiene`）→ `gh pr merge`。提交信息 conventional commits；宪法修订先记 `CHANGELOG.md` 再改正文。
4. 高频宪法约束提醒：金额一律 BIGINT 存分（换算集中 convert/ 层 MoneyUtil）；MyBatis-Plus 用法按 backend A.4.3（单表 lambdaQuery 链式、复杂 SQL mapper+XML、ASSIGN_ID、分页 maxLimit=2000、三大插件集中注册）；RabbitMQ 消费一律 @RabbitListener + 容器 AUTO 确认 + 幂等；常量 constants/（public final static）、枚举 enum/、目录 dto/vo/record/cache；Lua 走 resources/lua/ + Redisson 预注册 + `{业务功能}` hash tag；注释/日志全中文。

### PR-4 M14 骨架（IoT 通路技术验证，P0 核心验证物）——已完成（PR #7，dev@9107f92）

- Flyway：`iot` schema + `iot_device`/`iot_binding` 表 + `iot_telemetry` 超表（CREATE TABLE → `create_hypertable` 按天分区，分区列入唯一键 `(device_id, metric_code, occurred_at)`）+ 压缩（7 天后）与保留（明细 90 天）策略迁移——策略函数用 `add_columnstore_policy` 与 `add_compression_policy` 各实测一次后择一锁定（TASK.md T-R3-2 的实测即在本 PR 完成）。
- 消费链路：Qpid JMS 连接工厂（URI 显式 failover 参数，独立 `iot.amqp.*` 配置前缀与容器工厂）+ SmartLifecycle 消费者 + 标准遥测消息模型解析（四路同构，M14 Spec §3.1）+ 攒批（同设备哈希线程内 500-5000 条/批）批量写 TimescaleDB（唯一约束冲突忽略）+ **客户端确认**（IoTDA 语义：批量处理成功后统一确认；解析失败落 `iot_consume_error_log` 后确认抛弃——注意此处是 IoTDA/Qpid 的客户端确认，与 RabbitMQ AUTO ack 是两套，宪法 A.5-9/10）。
- 上行扇出：遥测入库后业务事件（设备状态/告警占位）经 `fy.topic` 发布 → `/ws/iot` STOMP 端点（P0 至少"遥测摘要"主题）推 workstation/bigscreen。
- 兜底与监控：`POST /ingest/iotda-fallback` HTTP 兜底端点（独立鉴权）+ 消费积压水位/断链时长双指标（Micrometer + actuator 暴露）。
- `iot-simulator`：模拟设备（**D-3 默认裁决：Java + Maven 子模块 `backend/iot-simulator`**，复用父 POM 工具链与 Dockerfile 策略；如用户改选 Node 另立顶层目录）经 MQTT+TLS 上行 IoTDA 测试产品；compose `--profile sim` 启动。
- images job 追加第三条 matrix（iot-simulator），移除 TODO 注释。
- 验收（P0 交付验证物）：`docker compose --profile sim up` → IoTDA→AMQP→TimescaleDB→WebSocket 端到端数据链路演示通过；断链 10 分钟重连恢复消费（T-R3-3 实测项一并完成回填）。

**用户需在 PR-4 前准备**（无法自动化）：华为云 IoTDA 测试实例 + AMQP 订阅凭证（AccessKey/Secret）+ 测试产品与设备一机一密三元组 → 填入本地 `.env`（`IOTDA_*` 六个变量，见 `.env.example`）；无实例时 PR-4 先交付代码与集成测试（模拟信封注入），端到端演示延后。
