## 一、修复清单（≥80 且无争议，2 项）

### SEC-01（原 BE-S1-03，置信 85，确认）
- **问题**：脱敏规则维护端点无角色门禁，构成提权解密链。任意登录用户可 `PUT /api/v1/patient/privacy-mask-rules/{ruleCode}` 将自身角色写入 ID_CARD/MOBILE/ADDRESS 规则的 exemptRoles（PrivacyMaskServiceImpl:99-117 每请求加载即时生效），再经 `POST /privacy/unmask` 全字段豁免短路角色豁免+诊疗关系双道门禁，解密读取任意患者身份证号/手机号/住址明文（仅留不可阻断的 SENSITIVE_QUERY 审计行）。
- **证据**：backend/fuyun-patient/src/main/java/com/fuyun/patient/controller/PrivacyController.java:148-153（updateRule 仅 @AuditLog(WRITE) 无角色门禁）；PrivacyMaskServiceImpl.java:106-115（exemptRoles/enabled 任意覆盖）；PrivacyServiceImpl.java:98-107（全字段豁免 exemptAll=true 短路双道门禁）。
- **修复方案**：脱敏规则维护端点（update/create/delete/disable 类写操作）增加 ADMIN 角色门禁——消费 RoleContextHolder（V303 已注入角色清单），非 ADMIN 返回 403；unmask 豁免链路不变。补集成测试：非 ADMIN 调规则维护 403 / ADMIN 正常 / unmask 行为保持。
- **影响面**：fuyun-patient 模块 PrivacyController + 服务层；对外契约仅新增「非授权 403」安全收口（属堵漏，非破坏）；需同步核验既有测试无依赖旧形态。

### SEC-02（原 BE-S1-07，置信 80，确认）
- **问题**：患者/就诊/病区三维零归属校验（IDOR）。任意登录用户传入任意 wardId/doctorId/patientId/visitId 即可横向读取他病区在区患者一览与详情卡（WardController.listByWard）、他科医生候诊列表（VisitController.patientQueue，doctorId 前端传入不与会话比对）、任意患者体征全量（VitalSignController listByPatient）、他病区任务/交接班/待复核清单与任意就诊护理记录（NursingTask/ShiftHandover/NursingRecord/Io 等）。
- **证据**：fuyun-nursing/controller/WardController.java:76-79；fuyun-outpatient/controller/VisitController.java:77-80；fuyun-nursing/controller/VitalSignController.java:76-79；fuyun-nursing/controller/PdaController.java:22（javadoc 自认 WARD 隔离随 M01 P1-later）；system 域 DataScopeType 全仓无运行期消费。
- **修复方案（最小行为保持）**：①请求参数含 doctorId 的端点（patientQueue 等）与认证会话身份比对，不一致返 403；②护士/医生侧按患者/就诊查询端点增加「会话可 identity 比对则比对」的最小守卫；③病区维度隔离若无现成归属数据模型（护士-病区归属），该子面登记转待裁决（禁新表设计），仅落地①②可行为保持部分。补测试：会话身份不匹配 403 / 匹配行为保持。
- **影响面**：fuyun-nursing / fuyun-outpatient 控制器层；对外契约仅新增「身份不匹配 403」收口；前端既有调用均传会话自身身份，行为保持。
