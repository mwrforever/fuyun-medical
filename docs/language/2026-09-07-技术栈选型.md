## 1. 文档头

本报告为 fuyun-medical 大型医疗管理系统的技术栈定稿文档，回答三个问题：

1. 各技术组件在 2026 年 9 月时点的**真实稳定版本**是什么（每项均给出来源 URL 与镜像 tag）；
2. dev/test 环境的 **Docker Compose 部署编排**如何设计（服务清单、拓扑、健康检查、网络卷、密钥注入约定）；
3. 选型与总 Spec 第 1.2 节技术基座、第 4 章决策 D1-D8 是否**零冲突**（逐条核对见第 9 节）。

本机环境约束（已确认兼容）：Java 17、Maven 3.9.x、Node 24、Docker Desktop for Windows；**pnpm 未安装**，环境准备要求见第 4.2 节。

## 2. 选型原则

1. **与总 Spec 决策对齐**：凡 §1.2 技术基座与 D1-D8 已锁定的技术路线（Spring Boot 3 模块化单体、PostgreSQL 16 + TimescaleDB、Redis、RabbitMQ 非 Kafka、Vue3 + TS + Element Plus、IoTDA AMQP 直连、MinIO/OBS、Nginx），本报告只做版本细化，不做路线变更；确需调整的（如 MinIO 社区版归档）在第 9 节显式标注裁决理由。
2. **优先当前稳定版，而非最新版**：选各组件官方当前 GA 稳定行；对刚 GA 不足一个季度、生态适配未收敛的大版本（TypeScript 7、JUnit 6、Testcontainers 2.x、SpringDoc 3.x）持保留态度，锁定上一稳定行并列入演进路径。
3. **长期支持优先**：运行时一律选 LTS 行（Java 17、Node.js 24 LTS、PostgreSQL 16、nginx stable 分支、RabbitMQ 4.3 LTS 类稳定行），避免"升级即重构"。
4. **社区生态与可维护性**：优先社区活跃、文档完善、国内云厂商有对应托管服务的组件（生产迁移路径短），例如 Redis/PostgreSQL/RabbitMQ 在华为云均有托管等价物。
5. **BOM 托管优先于自由版本**：凡被 Spring Boot BOM（`spring-boot-dependencies` 3.5.16）托管的依赖（Flyway、Spring AMQP、Jackson、JUnit、Mockito、Testcontainers），跟随 BOM 版本，禁止自行覆盖造成版本漂移；BOM 未托管的前端与工具类依赖用 lockfile（pnpm-lock.yaml / Maven parent 固定）锁定。
6. **版本可追溯**：每个版本号必须能在官方来源验证；镜像 tag 与代码版本一一对应，禁止 `latest` 漂移 tag 进入 compose 文件。

### 6.2 服务拓扑说明

```
                 ┌────────────── 开发者浏览器 / PDA 模拟器 ──────────────┐
                 │                                                      │
                 │ :80                                                  │ :8080（联调直连）
                 ▼                                                      │
              nginx ──静态资源（web-workstation / web-portal / web-bigscreen 构建产物）   │
                │  ├─ /api/**  ──反向代理──►  backend:8080              │
                │  └─ /ws/**   ──WebSocket 升级──►  backend:8080        │
                ▼                                                       ▼
   ┌──────────────────────────── backend（模块化单体，无状态，可 --scale 多实例）───────────────────────────┐
   │  postgres:5432（业务 schema + TimescaleDB 超表）   redis:6379（缓存/会话/锁/快照）                      │
   │  rabbitmq:5672（fy.topic / fy.dlx / fy.delay，quorum 队列）   minio:9000（S3 API）                     │
   │  华为云 IoTDA AMQP 订阅（出站 TLS，非容器网络）  ◄── iot-simulator（profile: sim，模拟设备经 IoTDA 上行） │
   └──────────────────────────────────────────────────────────────────────────────────────────────────┘
```

- **postgres**：`timescale/timescaledb` 镜像 = PostgreSQL 16 + TimescaleDB 扩展，一个服务承载"业务库 + 遥测时序库"；庝始化建库脚本放 `deploy/postgres/initdb/`（挂载到 `/docker-entrypoint-initdb.d`），内容仅两件事：建业务库、`CREATE EXTENSION IF NOT EXISTS timescaledb`。其余表结构/超表/压缩保留策略全部由 backend 的 **Flyway 迁移**创建（版本化、可重放，compose 不承载业务 DDL）。
- **redis**：单实例即可满足 dev/test；`maxmemory` 与淘汰策略（业务键 noeviction、快照键 volatile-lru 的差异化由应用 key 前缀约定承载，不在 broker 层拆分实例）。
- **rabbitmq**：`rabbitmq.conf` 仅设 `default_queue_type = quorum` 与管理台监听；交换机三件套（`fy.topic`/`fy.dlx`/`fy.delay`）与队列（`q.<消费者>.<事件>`）由 M20 治理构件在应用侧声明（M20 Spec §7 约定：私建交换机禁止），compose 不做任何队列预声明。
- **minio**：仅 dev/test 存在；桶创建由 backend 启动初始化（SDK 检查并创建），避免手工步骤。
- **nginx**：dev 环境挂载本地构建产物目录（前端 `pnpm build` 后热替换即可生效，无需重建镜像）；HTTPS/WSS 终结在生产由华为云 ELB/CDN 承担，dev 仅 HTTP；fuyun.conf 须内置 `/healthz` 静态 200 端点（`return 200`），供容器健康检查探测。
- **backend**：默认单实例。多实例验证方式：`docker compose up --scale backend=2`——backend 不发布 host 端口（经 nginx 反代），`--scale` 直接可用，用于验证 WebSocket 扇出（经 RabbitMQ）与 AMQP 消费者多实例（连接数受 IoTDA 单凭证 32 连接上限约束，14-iot Spec §9）——此为 P0 交付验证项之一。
- **iot-simulator**：P0 IoT 通路技术验证的模拟设备端（总 Spec §9 P0），用 `--profile sim` 隔离，日常开发不启动；其上行目标为华为云 IoTDA 测试产品（MQTT+TLS，一机一密凭证经环境变量注入），用于打通 IoTDA→AMQP→TimescaleDB→WebSocket 全链路。

### 6.3 健康检查与启动顺序设计

启动链路（全部用 `depends_on.condition: service_healthy`，禁止 `service_started` 裸依赖）：

```
postgres / redis / rabbitmq / minio （四者并行，互不依赖，各自 healthy）
        └──────────────┬───────────────────────┘
                       ▼
                    backend（四依赖全部 healthy 后启动；启动期内自带 Flyway 迁移，actuator 就绪即视为 healthy）
                       ▼
              nginx（backend healthy 后启动，避免代理 502 窗口）
              iot-simulator（backend healthy 后启动，仅 sim profile）
```

健康检查参数约定：`interval: 10s`、`timeout: 5s`、`retries: 5`；RabbitMQ 因首启初始化慢将 `start_period` 放宽到 90s；backend 的 health 端点用 actuator 的 readiness 语义（数据库/Redis/RabbitMQ 连通性纳入 health indicator），保证"healthy 即可用"。

### 6.4 网络与数据卷规划

- **网络**：单一自定义 bridge 网络 `fy-net`。仅 `nginx`（80）与联调期的 `postgres`（5432）、`redis`（6379）、`rabbitmq`（5672/15672）、`minio`（9000）发布宿主端口，`backend` 不发布端口（联调需要时用 profile `debug` 临时暴露 8080）；服务间一律以服务名经 `fy-net` DNS 解析互访。
- **named volumes 清单**：

| 卷名 | 挂载点 | 用途 |
| --- | --- | --- |
| `pg_data` | /var/lib/postgresql/data | 业务库 + TimescaleDB 全部数据（含 WAL） |
| `redis_data` | /data | RDB/AOF 持久化 |
| `rabbitmq_data` | /var/lib/rabbitmq | 队列持久化（quorum 队列元数据与消息） |
| `minio_data` | /data | 对象存储数据（仅 dev/test） |

- 前端构建产物与 nginx 配置为 **bind mount**（进入版本库的配置，非数据）；禁止把数据库数据放 bind mount（Windows 文件系统性能差且权限语义不一致）。

### 6.5 环境变量与密钥注入约定

对齐总 Spec 红线与 14-iot Spec FU-M14-01"密钥明文不入库"：**一切凭据经环境变量注入，禁止硬编码在 compose/代码/配置库中**。

- 仓库只提交 `.env.example`（模板，键齐全、值为空或占位说明），真实 `.env` 加入 `.gitignore` 不入库；
- compose 内一律 `env_file` + `${VAR}` 插值引用，禁止出现明文密钥字面量；
- IoTDA 凭证（实例接入地址、AMQP 用户名/密码、模拟设备一机一密三元组）同样走 `.env`，与云上真实凭证管理（FU-M14-01 凭证托管）分层；
- 敏感变量一览：数据库口令、Redis 口令、RabbitMQ 用户/口令、MinIO root 口令、IoTDA 接入凭证、短信/医保等外部接口密钥（后续阶段追加）。

### 6.8 dev / test / prod 三环境差异

| 维度 | dev（本机 Windows Docker） | test（CI：GitHub Actions） | prod（华为云，不在本机） |
| --- | --- | --- | --- |
| 编排载体 | 本报告设计的 docker-compose（单机全栈） | 不运行长期 compose；由 **Testcontainers** 按用例拉起与 compose 同版本 tag 的容器（PG16+Timescale、Redis 8.10.1、RabbitMQ 4.3.5），保证"测试中间件 = 开发中间件" | 托管服务：RDS for PostgreSQL 16（含 TimescaleDB 扩展，开通前与云厂商确认扩展白名单）、DCS for Redis、DMS RabbitMQ（或云上自建 4.3.x 集群）、OBS 对象存储、ELB + WAF 承接 Nginx 职责（HTTPS/WSS 终结） |
| 数据库 | compose 内 timescale 容器 | Testcontainers 容器 | RDS 高可用实例 + 同城备库（流复制，总 Spec §8：RPO≤15min/RTO≤4h） |
| 对象存储 | MinIO（社区最终版，内网隔离） | Testcontainers MinIO 或跳过（单元级 mock） | **华为云 OBS**（生命周期分层：在线 90 天→近线→归档，总 Spec §4.4） |
| IoT 链路 | iot-simulator（sim profile）→ 华为云 IoTDA 测试实例 | IoTDA 测试实例 + 回放用例 | IoTDA 标准版生产实例；告警 HTTP 兜底双通道（总 Spec §5.3-3） |
| 入口 | nginx:80（HTTP） | CI 内直连容器端口 | ELB/WAF + CDN，HTTPS/WSS |
| 密钥 | `.env`（本机） | GitHub Actions Secrets | 华为云 KMS/凭据管理服务（DEW） |
| 镜像来源 | 本地构建 | CI 构建后推送（GHCR 或华为云 SWR，见第 8 节） | SWR 私有仓库 + 镜像签名扫描 |

**本仓库 compose 的定位**：面向 dev/test 与 P0 端到端验证（IoTDA→AMQP→TimescaleDB→WebSocket 链路演示）；prod 环境由华为云托管服务承接，compose 不是 prod 交付物，但服务版本与 prod 托管版本严格对齐（避免"本地能跑、云上版本不同"）。

## 8. CI/CD 对接（GitHub Actions 设计描述，本报告不落 workflow 文件）

流水线分三个 job，全部在 `ubuntu-latest` runner 上执行：

1. **backend 构建**：`actions/setup-java@v6`（Temurin 17，Maven 依赖缓存）→ `mvn -B verify`：单元测试 + Testcontainers 集成测试（PG16+TimescaleDB、Redis 8.10.1、RabbitMQ 4.3.5 容器，与 compose 同 tag）+ JaCoCo 覆盖率门槛（对齐全局规范第四节）；失败即阻断合入，CI/CD 自动把关（全局规范第六节）。
2. **frontend 构建**：`pnpm/action-setup@v6`（读取 packageManager 字段自动装 pnpm 12.3.4）+ `actions/setup-node@v7`（Node 24，pnpm store 缓存）→ `pnpm install --frozen-lockfile` → `lint` → `type-check`（vue-tsc）→ `test` → `build`。
3. **镜像构建推送**：backend / nginx 前端产物 / iot-simulator 三镜像，tag 规则 `git sha` + `分支-latest`，推送 GHCR（test）或华为云 SWR（后续对接）；镜像内不打入任何密钥（第 6.5 节红线）。

所用 Actions 支持版本（2026-09 核实）：actions/setup-java v6.0.0（https://github.com/actions/setup-java/releases ）、actions/setup-node v7.0.0（https://github.com/actions/setup-node/releases ）、pnpm/action-setup v6.1.0（https://github.com/pnpm/action-setup/releases ）；三者均要求 runner 使用 Node 20+ 运行时（GitHub 托管 runner 已内置）。工具链基线：Docker Engine 29.8 / Compose v5.5.1（https://github.com/moby/moby/releases ；https://github.com/docker/compose/releases ），Compose 编写采用 Compose Specification 语法（不写已废弃的 `version:` 字段）。

## 9. 与总 Spec 决策的一致性核对表

| 决策 | 内容摘要 | 本报告结论 | 说明 |
| --- | --- | --- | --- |
| D1 | RabbitMQ 作为唯一自建 MQ（3.13+，quorum queue） | ✅ 遵守（版本显式裁决） | 选 RabbitMQ 4.3.5：满足"3.13+"下界且为当前稳定行；quorum 队列在 4.x 为默认主推并持续增强；TTL+DLX 延迟方案与 quorum 兼容（不引入 delayed-message 插件）；Spring AMQP 3.2 经 AMQP 0-9-1 与 4.x broker 完全兼容。4.0 起移除的 classic mirrored queue 本项目从未使用，无迁移负担 |
| D2 | 遥测直连 IoTDA AMQP 入 TimescaleDB，不经 MQ | ✅ 遵守 | Qpid JMS 2.11.0（AMQP 1.0，仅对接 IoTDA）+ TimescaleDB 2.29.2-pg16；compose 中 backend 出站连接 IoTDA，遥测不经 rabbitmq 服务 |
| D3 | 波形数据默认边缘降采样/不落库 | ✅ 遵守 | 基础设施按"体征/报警/事件级"数据量选型（TimescaleDB 明细 90 天+压缩 7 天后启用+两级聚合 1 年），存储策略由 Flyway 落库可配置 |

## 10. 演进与升级策略

### 10.1 小版本锁定与升级节奏

- **锁定方式**：后端依赖版本全部收敛到 parent POM/BOM；前端以 `pnpm-lock.yaml` + `packageManager` 字段锁定；容器镜像一律 pin 具体版本 tag（禁止 `latest`/`stable` 漂移 tag）。
- **升级节奏**：中间件（PG/TimescaleDB/Redis/RabbitMQ）小版本每季度评估一次，只取补丁版（第三位），不做跨小版本跳跃；框架小版本（Spring Boot 无 3.x 后续、Vue/Element Plus 补丁）跟随 lockfile 更新由 dependabot/renovate 提案、CI 全量测试把关后合入。

### 10.2 LTS 跟随

- Java：17 LTS（Temurin 维护至 2030-09）；下个评估点为 Java 21 LTS 迁移（Boot 3.x 内可直接升，属低风险升级）。
- Node.js：24 LTS 维护至 2028-04-30；在 24 转入维护期（2026-10 后）评估切换 Node 26 LTS。
- PostgreSQL：16 大版本支持至 2028-11（官方版本政策），生产 RDS 同版本对齐；PG 17/18 升级与 TimescaleDB 2.29.x 已兼容，作为存储层独立演进项评估。

### 10.3 Spring Boot 3.5.16 OSS 停更的专项对策（重要）

3.5.16 是 3.x 系列最后一个开源补丁版（2026-06-25），官方明确 OSS 支持至 2026-06-30，后续安全补丁仅商业支持（Tanzu Spring）或 4.x 行提供。本报告按总 Spec"必须 3.x"约束选定 3.5.16，并给出三个有序选项供总 Spec 修订时裁决：

1. **默认策略**：冻结 3.5.16，依赖镜像化运行环境（自建基础镜像统一修复 OS 层 CVE）+ 应用层加固缓解应用框架层风险，并建立 CVE 监控（NVD/GitHub Advisory 订阅 spring-boot/spring-framework）；
2. **计划迁移**：在总 Spec 允许的修订窗口启动 Boot 3.5 → 4.0（新 LTS）迁移评估，Spring AMQP 3.2→4.0、JUnit 5→6、Testcontainers 1.x→2.x、SpringDoc 2.8→3.1 为配套迁移项，预计随 P1 完成后的首个迭代窗口执行；
3. **商业支持**：若项目进入等保测评/医保结算等强合规审计阶段且 4.x 迁移未完成，评估 Tanzu Spring 订阅获取 3.5 行补丁。

### 10.4 MinIO 停维的专项对策

- dev/test 冻结 `RELEASE.2025-09-07T16-13-09Z`，容器仅绑定内网/回环、强口令、不暴露公网，规避无补丁风险敞口；
- 应用对象存储访问层一律走 S3 SDK + 配置化 endpoint（OBS 兼容 S3 API），生产切换 OBS 仅改配置不改代码；
- 若后续出现不可接受的安全通告，dev 侧备选：直连华为云 OBS 测试桶，或将 MinIO 数据卷定期清空重建（dev 数据可再生）。
