## §1 后端构建与测试细则（backend/AGENTS.md C.4 / C.5 / C.6 素材）

### 1.1 Maven 命令全量清单

| 用途 | 命令（在 `backend/` 目录执行） | 说明与边界 |
| --- | --- | --- |
| 全量门禁（CI 与本地交付前必跑） | `mvn -B -ntp verify` | 一条命令串联：spotless:check（默认绑 verify）→ surefire 单测 → failsafe 集成测试（Testcontainers）→ jacoco:check。任一失败即构建失败 |
| 快速单测反馈（本地开发循环） | `mvn -B test` | 仅 surefire 单测，不触发 failsafe/覆盖率门禁；禁止以此作为合并依据 |
| 指定模块门禁（含依赖模块） | `mvn -B -pl billing -am verify` | `-pl` 限模块、`-am` 带上依赖模块；模块名 = fuyun-<模块>（system/patient/…/integration 共 21 个，见总 Spec §4） |
| 仅跑集成测试（调试） | `mvn -B failsafe:integration-test failsafe:verify -pl <module>` | failsafe 两 goal 手动执行；需 Docker 运行中 |
| 调试单个集成测试类 | `mvn -B verify -Dit.test=OrderFlowIT -Dtest=NoSuchTest -Dsurefire.failIfNoSpecifiedTests=false` | `-Dit.test` 仅过滤 failsafe；`-Dtest=NoSuchTest` + `failIfNoSpecifiedTests=false` 让 surefire 空跑不报错 |
| 格式修复（本地，写前/提交前） | `mvn -B spotless:apply` | 自动改写源码；`spotless:check` 为只读校验，与 CI 同源 |
| 覆盖率报告（单模块） | `mvn -B verify` 后查看 `<module>/target/site/jacoco/index.html` | report goal 绑定 verify 阶段（配置见 §1.5） |
| 覆盖率聚合报告（只读总览） | 装配模块 `target/site/jacoco-aggregate/index.html` | report-aggregate 产物，仅报告用，不作为门禁口径（理由见 §1.4） |
| 依赖漏洞审计 | `mvn -B -ntp org.owasp:dependency-check-maven:13.0.0:check` | CI 中以 secret 注入 `NVD_API_KEY`（见 §1.6）；建议放独立定时 job |
| 版本漂移巡检 | `mvn -B -ntp versions:display-dependency-updates versions:display-plugin-updates` | versions-maven-plugin（MojoHaus），列依赖/插件可升级项，人工评估不自动升（对齐技术栈报告 §10.1"lockfile + 自动提案 + CI 把关"） |

### 1.2 单测（surefire）与集成测试（failsafe）分离约定

| 条目 | 依据（一句话） | 来源 URL | 适用版本 | 取舍建议 |
| --- | --- | --- | --- | --- |
| 命名规则：单测 `*Test.java`，集成测试 `*IT.java` | Failsafe 默认只拾取 `**/IT*.java`、`**/*IT.java`、`**/*ITCase.java`；Surefire 默认拾取 `**/Test*.java`、`**/*Test.java`、`**/*Tests.java`、`**/*TestCase.java`——默认模式天然互斥，零配置分离 | https://maven.apache.org/surefire/maven-failsafe-plugin/ | maven-surefire-plugin / maven-failsafe-plugin（版本随 spring-boot-starter-parent pluginManagement，不自定版本） | **采纳**。补充约定：Testcontainers 编排类（容器定义基类、测试工具）放 `src/test/java` 非 `*Test`/`*IT` 命名的类中，避免被任一插件误拾取 |
| failsafe 标准绑定写法：`integration-test` + `verify` 两 goal 显式声明在父 POM pluginManagement/executions | 官方文档：`failsafe:integration-test` 默认绑 `integration-test` 阶段、`failsafe:verify` 默认绑 `verify` 阶段；fairsafe 失败不立即中断、保证 post-integration-test 清理容器后于 verify 阶段报失败——因此**必须用 `mvn verify` 触发而非 `mvn integration-test`** | https://maven.apache.org/surefire/maven-failsafe-plugin/ | 同上 | **采纳**。写法：`<plugin>maven-failsafe-plugin</plugin><executions><execution><goals><goal>integration-test</goal><goal>verify</goal></goals></execution></executions>`（官方 usage 原样） |
| 不引入"集成测试 profile 开关" | 单测与集成测试由命名规则分离，`verify` 全量执行即全局规范"全量单测+集成测试过才能合主干"的载体；加 profile 反而制造"跳过集成测试"的人工绕过口子 | 全局规范第四节 + 上行官方机制 | — | **不做 profile**。CI 与本地跑同一命令 `mvn verify`，杜绝环境差异 |

### 1.4 JaCoCo 多模块覆盖率门禁：两种模式对比与推荐

| 模式 | 做法 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- | --- |
| **a) 每模块 `jacoco:check` 绑 verify（推荐）** | 父 POM pluginManagement 统一配置 prepare-agent + check；各业务模块以最小覆盖自行声明 rule（BUNDLE/LINE ≥ 0.80；核心包用 PACKAGE 级 rule + `<includes>` 要求 1.00）；21 个模块继承后按模块微调 excludes | 官方 `check` goal 直接支持、失败即构建失败且**失败点精确定位到模块**；数学上"各模块 ≥ 80% ⇒ 全局聚合 ≥ 80%"，等价满足全局口径；核心包 1.00 天然按模块/包名声明，跨模块无歧义 | 模块数多，阈值配置重复（由父 POM 收敛后可接受）；"跨模块公共代码被谁覆盖"口径需约定 | **推荐采纳 a** |
| b) 聚合模块 merge exec 后自定义 check | report-aggregate 模块（或装配模块）聚合 exec，再对聚合数据跑 check | 单一全局数字，观感直观 | **官方已知限制：`check` 不支持直接对聚合报告执行**（jacoco issue #902），需社区变通（report-aggregate 只出报告、门禁逻辑要自己拼），存在实施不可控风险；失败无法定位到模块 | 不采纳；聚合仅用于**只读报告**（report-aggregate 出 `jacoco-aggregate` 总览） |

依据 URL：check goal 官方文档 https://www.eclemma.org/jacoco/trunk/doc/check-mojo.html ；聚合限制 https://github.com/jacoco/jacoco/issues/902 ；多模块官方建议 https://www.eclemma.org/jacoco/trunk/doc/maven.html 与 report-aggregate https://www.eclemma.org/jacoco/trunk/doc/report-aggregate-mojo.html 。

**父 POM pluginManagement 配置要点（可直接落 pom 的骨架）：**

```xml
<!-- jacoco-maven-plugin 不在 Spring Boot 3.5.16 BOM/pluginManagement 托管范围（两个 pom 直查均无 jacoco 条目），须在父 POM 显式锁定版本 -->
<plugin>
  <groupId>org.jacoco</groupId>
  <artifactId>jacoco-maven-plugin</artifactId>
  <version>0.8.15</version>
  <executions>
    <execution>
      <id>prepare-agent</id>
      <goals><goal>prepare-agent</goal></goals>
    </execution>
    <execution>
      <id>report</id>
      <phase>verify</phase>
      <goals><goal>report</goal></goals>
    </execution>
    <execution>
      <id>check</id>
      <goals><goal>check</goal></goals>
      <configuration>
        <!-- 排除项：配置类/DTO/生成代码/启动类不计入分母（惯例清单，见 §1.5） -->
        <excludes>
          <exclude>**/config/**</exclude>
          <exclude>**/dto/**</exclude>
          <exclude>**/*Application.class</exclude>
          <exclude>**/generated/**</exclude>
        </excludes>
        <rules>
          <!-- 非核心：模块整体（BUNDLE）行覆盖 ≥ 80% -->
          <rule>
            <element>BUNDLE</element>
            <limits>
              <limit><counter>LINE</counter><value>COVEREDRATIO</value><minimum>0.80</minimum></limit>
            </limits>
          </rule>
          <!-- 核心包（资金/交易/支付/订单状态机/认证权限/第三方回调）：行覆盖 100%，逐包声明 -->
          <rule>
            <element>PACKAGE</element>
            <includes><include>com.fuyun.billing.settlement</include></includes>
            <limits>
              <limit><counter>LINE</counter><value>COVEREDRATIO</value><minimum>1.00</minimum></limit>
            </limits>
          </rule>
        </rules>
      </configuration>
    </execution>
  </executions>
</plugin>
```

**版本锁定依据**：jacoco-maven-plugin latest 为 0.8.15（2026-06-05，经 https://repo1.maven.org/maven2/org/jacoco/jacoco-maven-plugin/maven-metadata.xml 核实）；spring-boot-dependencies-3.5.16.pom 与 spring-boot-starter-parent-3.5.16.pom 直接下载核验均不含任何 jacoco 条目（dependencies 仅管 surefire 3.5.6）——该插件版本必须显式声明，不存在"随 BOM 托管"的默认值。

check goal 语法事实（官方 check-mojo 文档核实）：`element` 允许 `BUNDLE/PACKAGE/CLASS/SOURCEFILE/METHOD`；`counter` 允许 `INSTRUCTION/LINE/BRANCH/COMPLEXITY/METHOD/CLASS`；`value` 允许 `TOTALCOUNT/COVEREDCOUNT/MISSEDCOUNT/COVEREDRATIO/MISSEDRATIO`（无 `LINECOVEREDRATIO` 这种写法，是 counter+value 组合）；`check` 默认绑 `verify` 阶段；比率 0.80 与 80% 等价。

### 1.5 覆盖率排除项惯例（excludes 清单）

| 排除模式 | 理由 |
| --- | --- |
| `**/config/**`、`**/*Properties.class`、`**/*Configuration.class` | 纯配置装配代码，无业务分支 |
| `**/dto/**`、`**/entity/**`（视团队约定，二选一并全程一致） | 数据载体无逻辑 |
| `**/*Application.class`、`**/*Application$*.class` | Spring Boot 启动类 |
| `**/generated/**`、jOOQ/MapStruct 等注解处理器或代码生成器产出的类 | 生成代码不可控 |
| Flyway 迁移 SQL 侧 | 本就不参与编译统计 |

### 3.7 分支保护规则操作指引（最终强制点）

1. 仓库 **Settings → Branches → Branch protection rules → Add rule**（经典入口；若仓库启用 Rulesets 亦以同等配置建 ruleset），Branch name pattern 填 `main`。
2. 勾选 **Require a pull request before merging**，Required approvals 填 `1`（全局规范"要求 1 个 PR 审核"）。
3. 勾选 **Require status checks to pass before merging**，在搜索框逐个添加与 ci.yml 中 job **check 名称精确一致**的条目：check 名称 = job 的 `name:` 字段值（未写 `name:` 时为 job id）。方案 B 必须纳入：`backend`、`frontend`、`images`、`commitlint`、`hygiene`——**建议每个 job 显式写 `name:`，且名称使用固定 ASCII（如 `backend / verify`），避免中文或动态名导致匹配失败**。
4. 勾选 **Require branches to be up to date before merging**（必须与 main 最新同步，配合 concurrency 取消旧跑）。
5. 勾选 **Do not allow bypassing the above settings**——全局规范"禁止人工绕过"的机器化落点（管理员亦受约束）。
6. （可选）Require linear history（rebase/squash 合并，保证回滚粒度）。

依据：https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/managing-protected-branches/managing-a-branch-protection-rule ；skipped/pending 语义见 §3.3 同页文档。

**Dockerfile 编写规范（backend/Dockerfile 要点，可直接落盘的骨架约定）：**

```dockerfile
# ===== 构建层：Maven + JDK17，依赖拷贝先于源码拷贝以命中层缓存 =====
FROM maven:3.9-eclipse-temurin-17 AS build
WORKDIR /workspace
COPY backend/pom.xml backend/*/pom.xml ./            # 先拷全部 pom
RUN mvn -B -ntp dependency:go-offline                 # 预热依赖层（源码变动不失效）
COPY backend/ ./
RUN mvn -B -ntp package -DskipTests                   # 测试已由 CI 前置 job 门禁，镜像层不重复跑

# ===== 运行层：JRE 17 + curl（健康检查依赖，技术栈报告 FJ-01 既定）=====
FROM eclipse-temurin:17-jre
RUN apt-get update && apt-get install -y --no-install-recommends curl \
    && rm -rf /var/lib/apt/lists/* \
    && useradd -r -u 1001 fuyun                       # 非 root 运行
USER fuyun
WORKDIR /app
COPY --from=build --chown=fuyun:fuyun /workspace/<app-module>/target/*.jar app.jar
EXPOSE 8080
ENTRYPOINT ["sh", "-c", "exec java $JAVA_OPTS -jar app.jar"]
```

规范要点清单（逐条全局约束）：① 多阶段构建，构建层与运行层分离压体积；② 运行层基底 `eclipse-temurin:17-jre` 且**必须安装 curl**（compose 健康检查探针依赖，基底不含）；③ 非 root 用户运行（useradd 固定 uid）；④ 依赖拷贝（pom + go-offline）先于源码拷贝，层缓存友好；⑤ `.dockerignore` 必备：`target/`、`.git/`、`node_modules/`、`docs/`、`*.iml`，防上下文膨胀与密钥误打入；⑥ 镜像内不打入任何密钥（技术栈报告 §6.5 红线，凭据一律运行时 env 注入）；⑦ web 产物镜像：构建阶段 `node:24`（corepack 启用 pnpm 12.3.4）+ 运行阶段 `nginx:1.30.4`，与 dev 环境镜像版本严格一致。
