### 1.1 Flyway 11.7.2 迁移规范

| 条目 | 依据（一句话） | 来源 URL | 适用版本 | 取舍建议 |
| --- | --- | --- | --- | --- |

| 版本号编排候选 A：模块分段全局自增 | 单库单 `flyway_schema_history` 表下 Flyway 对所有 location 的版本做全局排序，模块各自从 V1 起编必然冲突 | https://documentation.red-gate.com/fd/january-2021-handling-multiple-schemas-in-the-same-database-with-flyway-212140936.html | Flyway 11.x | 预判推荐：公共库表占用低位号段（如 V1-V99），每个 Maven 模块固定百位号段（如患者域 V100-V199、医嘱域 V200-V299），冲突可静态发现且顺序可读；配套 CI 校验"号段归属 + 版本唯一" |
| 版本号编排候选 B：全局时间戳版本（yyyyMMddHHmmss） | 时间戳天然全局唯一有序，多分支并行开发不易撞号 | https://dev.to/kirekov/flyway-migrations-naming-strategy-in-a-big-project-51fp | Flyway 11.x | 备选：号段方案与时间戳方案二选一；时间戳方案在长周期分支合并时仍会出现"小版本晚于大版本落库"，同样受 outOfOrder 约束，可读性劣于分段号，故不作首选 |

| baseline 仅用于存量库接入 | `baseline-on-migrate` 针对"非空库且无 history 表"场景自动打基线，全新空库无需启用 | https://documentation.red-gate.com/fd/flyway-baseline-on-migrate-setting-277578974.html | Flyway 11.x | 采纳：本项目从零建库，全环境 `baseline-on-migrate=false`；仅当未来对已有 HIS 存量库启用 Flyway 时才配置 baseline-version |

| --- | --- | --- | --- | --- |

| 时间分区列必须包含在主键/唯一约束中 | hypertable 的分区键是唯一索引的必需组成部分，遗漏会在 `create_hypertable` 阶段直接报错，是迁移失败最高频原因 | https://stackoverflow.com/questions/67704790/ | TimescaleDB 2.29.x | 采纳为规范：`iot_telemetry` 主键形如 `(设备ID, ts)` 或单独使用 `(ts, 序列)`，设计评审时静态检查 |
| 压缩策略迁移化：先 `ALTER TABLE ... SET (timescaledb.compress [, compress_segmentby])`，再加策略 | 官方 API 文档明确：压缩策略的前提是先在表上开启 compress 属性，策略才可添加 | https://github.com/timescale/docs/blob/latest/api/compression/add_compression_policy.md | TimescaleDB 2.29.2 | 采纳：压缩开启语句与策略语句写入独立版本化迁移，不依赖运行时手工执行 |
| 压缩策略函数选型：`add_compression_policy` 自 2.18.0 起标记弃用，由 `add_columnstore_policy` 取代但"仍受支持、暂不要求迁移" | 官方 API 文档在 2.29 时点同时保留两函数，弃用说明明示兼容承诺 | https://github.com/timescale/docs/blob/latest/api/compression/add_columnstore_policy.md （压缩总览 https://www.tigerdata.com/docs/build/how-to/basic-compression ） | TimescaleDB 2.29.2 | 建议：沿用技术栈报告"7 天后启用压缩"定稿值，函数层面 P0 技术验证时对两函数各做一次实测后择一锁定（{待调研项} 见 §4）；新代码倾向 `add_columnstore_policy`，避免基于弃用 API 写规范 |
| 保留策略迁移化：明细 90 天 `add_retention_policy`，降采样聚合 1 年 | 官方推荐保留与压缩配对使用：先压缩再到期丢弃整 chunk，磁盘占用全程最小化 | https://www.tigerdata.com/docs/build/data-management/data-retention/create-a-retention-policy | TimescaleDB 2.29.2 | 采纳：90 天/1 年为定稿默认值写入迁移；聚合表（1 年）为普通表或 continuous aggregate，其清理策略须在聚合方案定稿时一并迁移化 |
| 策略添加顺序：压缩 → 保留 | 保留策略先于压缩生效会把未压缩数据直接删除，丧失降采样聚合窗口 | https://www.tigerdata.com/docs/build/data-management/data-retention/create-a-retention-policy | TimescaleDB 2.29.x | 采纳：同一迁移内先压缩后保留；两者尽量各自独立版本，便于单独调整阈值 |

| 禁用任何 ORM/框架级自动 DDL | 无论何种数据访问技术，自动建表改表（如 JPA `ddl-auto` 非 validate 模式）都会绕过 Flyway 使 schema 演进不可追溯 | https://docs.spring.io/spring-boot/3.5/reference/data/sql.html （Spring Boot 3.5 参考中 JPA `ddl-auto` 与迁移工具的关系） | Spring Boot 3.5.16 | 采纳为硬规范：无论 ORM 选型结果如何，生产与测试环境一律禁用自动 DDL（若选 JPA 则 `ddl-auto=validate`；MyBatis/jOOQ 天然无自动 DDL，亦禁止引入额外的 schema 管理工具），全部 DDL 唯一入口为 Flyway |

### 1.4 事务与查询普适约束

| 条目 | 依据（一句话） | 来源 URL | 适用版本 | 取舍建议 |
| --- | --- | --- | --- | --- |
| 只读查询标注只读事务 | `readOnly=true` 是优化提示而非写保护：数据访问层可借此跳过脏检查/设连接只读，Spring 官方声明其不阻止写操作 | https://docs.spring.io/spring-framework/reference/data-access/transaction/declarative/annotations.html | Spring Framework 6.2.19（BOM 托管） | 采纳：查询服务方法统一标注只读事务（无论何种数据访问技术，以 Spring 事务抽象为准）；不得依赖其做写拦截，写保护由权限与代码评审保证 |
| 大批量写入分批提交（遥测批量落库） | JDBC batch + `reWriteBatchedInserts` 为常态写入最优解，超大批量（历史回灌）COPY 快于批量 INSERT 数倍 | https://sqg.dev/blog/java-postgres-insert-benchmark/ ；INSERT/批量/COPY 对比 https://www.tigerdata.com/learn/testing-postgres-ingest-insert-vs-batch-insert-vs-copy | pgjdbc 42.7.11 | 建议：IoTDA 消费落库按 500-5000 条/批聚合后批量写入（匹配"快速落库+批量化"HA 要求）；单批事务独立提交，禁止单事务吞全量；批量回灌场景走 `CopyManager` COPY 通道 |
| 禁止长事务：事务内禁远程调用、消息发送与人工等待点 | 长事务占用池连接（池上限仅 10-20）并放大锁冲突；MQ 发送置于事务提交后可避免"回滚了但消息已发出" | https://github.com/brettwooldridge/hikaricp （池大小与占用论证）；发送时机实践 https://www.rabbitmq.com/tutorials/tutorial-seven-java | Spring Boot 3.5.16 | 采纳为硬规范：事务边界内只做本地库操作；对外调用（MQ/OBS/第三方）在事务提交后执行，确需原子性时另立规范（outbox 模式）评审 |
| 金额字段 `NUMERIC(18,2)`，服务端以十进制类型计算，禁 float/double/PG `money` 类型 | PG 官方定义 numeric 为精确十进制类型适合货币；`money` 类型 locale 绑定、浮点有二进制误差，社区共识弃用 | https://www.postgresql.org/docs/current/datatype-numeric.html ；类型对比 https://stackoverflow.com/questions/15726535/which-datatype-should-be-used-for-currency | PostgreSQL 16.15 | 采纳：DDL 一律 `NUMERIC(18,2)`（总 Spec 定稿）；无论 ORM 选型结果，应用侧必须映射为十进制类型（Java `BigDecimal`），禁止浮点参与金额运算；舍入规则（HALF_UP）在费用模块统一封装 |
| 索引变更一律走 Flyway 迁移 | 索引属于 schema 演进的一部分，线上手工建索引会造成环境间执行计划漂移且 history 表不可知 | https://github.com/flyway/flywaydb.org/blob/gh-pages/documentation/concepts/migrations.md | Flyway 11.7.2 | 采纳：`CREATE INDEX / DROP INDEX`（含 CONCURRENTLY 变体）全部进迁移文件；大数据表建索引评估 `CREATE INDEX CONCURRENTLY`（其不能在事务内执行，该迁移需 Flyway 的事务外执行配置，实施时验证 {待调研项}） |
| 审计字段统一维护：候选 A 数据库触发器/默认值 | 触发器保证任何写路径（含手工 SQL、其他程序）时间戳不可绕过、不可篡改，等保审计友好 | https://dev.to/kenzura/why-application-layer-audit-trails-fail-and-how-postgresql-triggers-fix-it-3h4h | PostgreSQL 16.15 | 预判推荐混合模式：`created_at`/`updated_at` 由数据库维护（`DEFAULT now()` + `updated_at` 触发器），`created_by`/`updated_by` 由应用层统一注入（数据库无从得知业务用户身份）；审计字段清单与命名在 A.4 规范中定稿 |
