## 1. 模块定位与边界

**职责**：本模块是全院运营与质量数据的唯一分析域与指标口径权威，六项职责：① 指标中台——指标字典（原子/派生指标、口径元数据、口径版本）、T+1 指标装配（只读汇总库）、指标快照与阈值预警；② 综合报表——门诊/住院工作量、收入、药占比/耗占比、平均住院日等固定报表与指标×维度自定义报表，生成/导出/推送全留痕；③ 管理驾驶舱——运营/质量/设备三视图 BI 大屏（web-bigscreen）与管理端驾驶舱（web-workstation）；④ 医疗质量指标——危急值及时率、病历质量、不良事件等指标统计（对齐电子病历分级评价、医疗质量安全核心制度监测、NCIS 口径），供评级/评审举证导出；⑤ 统计上报——卫健委卫生统计（卫健统月报/年报）与国家医疗质量数据抽样调查的数据加工、勾稽校验、任务调度、退回重报（传输经 M20）；⑥ 绩效统计——科室/医疗组/医生工作量与收入贡献统计，输出绩效数据集对接外部绩效系统（不做绩效核算）。

**非职责**：业务数据的权威生产与存储（归各业务模块，本模块只经其统计 API 与事件取数，不复制明细）；设备运行实时大屏（在线率/告警/遥测吞吐归 M14，FU-M14-13）；病案首页专业条线上报的内容加工（归 M09，FU-M09-09，本模块统计上报为全院汇总条线，见第 9 节边界）；绩效核算引擎与分配方案（归外部绩效系统，本模块只输出统计口径数据集）；患者级明细存储（本模块 schema 不落任何患者级数据，明细钻取实时调源模块 API）；财务总账凭证（归外部 HRP）。

**模块红线**：
1. 只读分析：本模块对任何业务模块零写接口，不参与任何业务事务、不回写业务状态；指标一律为只读快照。
2. 禁止跨模块读表：全部取数经源模块对外统计 API 或领域事件；收入类数据一律日终调 M13 收入统计 API（对齐 M15 红线 2 同款约束），不消费 `billing.*` 事件载荷做数据归集。
3. 指标口径唯一权威在本模块 indicator_definition：任何对外发布的数字（报表/大屏/上报/绩效）必须引用已发布指标，禁止界面与查询硬编码口径。
4. 上报数据一经上报即生成不可变冻结快照；退回重报生成新版本，旧版本与退回原因全程留痕可溯。
5. 本模块 schema 不落患者级明细；驾驶舱钻取实时调源模块查询 API，并按 M01 数据范围鉴权（汇总数据天然脱敏，明细权限归源模块）。

## 2. 调研依据

1. **国家三级公立医院绩效考核（"国考"）指标体系**：国办发〔2019〕4 号确立医疗质量、运营效率、持续发展、满意度 4 个一级指标，细化为 14 个二级指标、55 个三级指标；其中大量指标要求信息系统可提取可核算（门诊人次数与出院人次数比、出院患者手术占比、平均住院日、医疗服务收入（不含药品、耗材、检查检验收入）占医疗收入比例、人员支出占业务支出比重、收支结余、门诊/住院次均费用增幅等），数据质量直接决定得分。（来源：https://www.gjxfj.gov.cn/gjxfj/fgwj/gwywj/webinfo/2019/01/1590610502215319.htm ；https://html.rhhz.net/ZGWSZY/html/2021-3-268.htm ；http://journal.healthpolicy.cn/html/20200203.htm ）
2. **卫生统计法定上报**：全国卫生资源与医疗服务统计调查制度要求医疗机构填报年报表（卫健统 1-1 表至 1-8 表）及月报表，经国家卫生健康统计网络直报系统上报，报表间存在人力/床位/收入/工作量的勾稽关系；填报数据为依法统计义务。（来源：https://www.stats.gov.cn/fw/bmdcxmsp/bmzd/202506/t20250605_1960058.html ）
3. **NCIS 医疗质量数据上报**：国家医疗质量管理与控制信息网（NCIS）每年组织全国医疗质量数据抽样调查，覆盖数千项质控指标（2024 年调查涉及 3000+ 指标），要求医疗机构按统一口径从信息系统提取年度数据填报。（来源：https://www.ncis.cn/ ；https://www.huimei.com/news/1720766449561.html ）
4. **医疗质量安全核心制度监测指标**：国家卫健委发布《医疗质量安全核心制度落实情况监测指标（2025 年版）》，为危急值、病历质量等院内质量指标的官方监测口径来源。（来源：https://www.chima.org.cn/Html/News/Articles/17437.html ）
5. **医院数据驾驶舱生产实践**：医院数据驾驶舱将运营、医疗、管理各领域关键数据经可视化大屏/仪表盘呈现，本质是"指标体系+可视化+异常预警"的决策支持载体；头部实践（华讯院长驾驶舱等）强调自设指标体系、实时监测与关键指标异常预警。（来源：https://www.finereport.com/blog/article/69dd984812cf5a9eb19c6dba ；https://www.eccom.com/industry/hospitaldirector ）
6. **大屏与驾驶舱定位差异**：大屏是"数据橱窗"（呈现与感知），管理驾驶舱是"分析工作站"（监控与决策），两者受众与刷新诉求不同——运营驾驶舱以 T+1 快照为主即可满足决策时效，实时性让位于口径正确性。（来源：https://www.smartbi.com.cn/article/170 ；https://www.finebi.com/blog/article/69b081f32c6ebd90bcc26ae9 ）
7. **指标口径管理方法论**：数仓指标管理成熟模型将指标分为原子指标（业务过程不可再拆分的度量）与派生指标（原子指标+时间周期+修饰词/维度），配套指标字典统一登记口径，解决"同名指标多口径、各部门数字对不上"的治理难题。（来源：https://help.aliyun.com/zh/dataworks/user-guide/data-metric ；https://zhuanlan.zhihu.com/p/448733810 ）

## 3. 方案推导（关键设计点选型）

### 3.1 指标数据架构：直查 OLTP 业务表 vs 事件驱动实时汇总 vs T+1 事件增量+日终批量装配只读汇总库

| 方案 | 说明 | 评估 |
| --- | --- | --- |
| 各模块 OLTP 库直查 | 报表/大屏查询直接跨模块聚合业务表 | 违反 README 跨模块红线（禁止跨模块读表）与总 Spec D4 模块边界；全院全年量级的分析聚合与门诊收费高峰争抢 OLTP 资源，直接威胁"挂号/收费 P95 < 500ms"（总 Spec 8）；口径散落在各查询语句中无法治理与审计 |
| 事件驱动实时汇总 | 订阅全部领域事件流实时累加指标 | 上游逆向链路密集（退费红冲、报告更正、首页修订——M13/M07/M09 已定稿），实时流必须双向对冲且重放全量历史才可回溯修正，复杂度与事件流量远超收益；驾驶舱是管理决策载体而非实时监控（调研依据 6），T+1 已满足时效 |
| **T+1 事件增量+日终批量装配只读汇总库（选定）** | `ops` schema 建只读汇总库：ops_daily_fact 日事实宽表（源模块统计 API 取数落表）+ indicator_snapshot 指标快照（按指标定义派生）；**主链路=日终批量装配**（拉取各模块统计 API、记录取数批次 source_pull_log，T+1 可重算幂等）；**辅链路=事件增量**（仅订阅少量领域事件维持当日盘中角标与装配触发信号）；当日退费红冲等修正经次日凌晨重算自然收敛 | 分析负载与 OLTP 物理隔离（查询只触 ops 只读库）；口径收敛到指标字典一处；取数批次留痕使任一快照可解释可审计；与 M15 效益装配"T+1 日终批量"已定稿结论同构，取数方式统一；实时性让位于正确性符合管理驾驶舱定位 |

**数据源提供方式结论**：优先复用各模块已声明的统计 API——M13 收入统计（按收费项目×执行科室×日期聚合接口位）、M07 `/stats/critical-value-indicators|tat|workload`、M08 影像报告/检查工作量统计、M09 `/stats/qc-indicators` 与首页/编码统计、M05 `/stats/nursing-workload` 与破码率/不良事件统计、M10 手术工作量统计、M15 `/stats/*` 装备指标与 `/benefit/*` 效益汇总、M03/M04 工作量统计（接口位）、M16/M17/M18 stats API（接口位，P6 启用：M16 呼叫响应时长与医废重量、M17 体检人次与随访率、M18 互联网诊疗量与配送时效，见 §8 与偏差 5，M-21 裁决采纳在本期指标 data_sources 登记三者 stats API）；事件订阅仅承担"当日角标+装配触发信号"职能；禁止直查任何业务 schema。

### 3.2 指标口径管理：界面/报表硬编码 vs 指标字典元数据化（原子/派生/口径版本）+多口径冲突治理

| 方案 | 说明 | 评估 |
| --- | --- | --- |
| 界面/报表硬编码口径 | 口径写在每张报表、每个大屏组件的查询里 | 同名指标多口径并存且无治理（如"平均住院日"存在出院者口径与在院口径、"药占比"分母存在含/不含耗材两派），各处数字互相对不上，管理决策与上报举证失信；口径变更无版本、无审计，历史数字不可重现 |
| **指标字典元数据化（选定）** | indicator_definition 统一登记：原子指标（门诊人次/药品收入/占用床日等不可再分度量）与派生指标（原子指标+时间周期+维度修饰，如"某科室某月药占比"）；逐指标登记计算口径（分子/分母/筛选条件/精度规则）、可用维度、数据源引用、责任模块、口径版本与生效区间；对外发布一律引用指标 code；**多口径冲突治理**：同一业务概念多口径并存时逐口径独立建档并显式命名（如"平均住院日-出院者口径[国考]"与"平均住院日-在院口径[院内监控]"），每指标指定唯一"对外发布口径"（release_flag），其余口径标注适用场景；口径变更版本化，旧快照按旧口径版本可重现 | 原子/派生两层模型为数仓指标管理成熟方法论（调研依据 7）；多口径"显式化"而非"消灭"，兼顾国考口径、院内监控口径与上报口径三套现实；版本化支撑"上报后不可变"（红线 4）与历史可重现，直接回应"55 个指标评分取数可核算"的国考要求（调研依据 1） |

### 3.3 上报数据链：各模块分散上报 vs ETL 工具直连业务库 vs M19 统一加工+三级勾稽+M20 传输

| 方案 | 说明 | 评估 |
| --- | --- | --- |
| 各业务模块分散上报 | 各模块各自生成与传输上报数据 | 卫生统计年报跨模块勾稽（人力[ M01]/床位与工作量[M04]/收入[M13]同现多表）无处统一校验；任务与回执状态分散；同一数据多处加工口径必然漂移（调研依据 2 的表间勾稽要求落空） |
| ETL 工具直连业务库 | 引入 ETL 从业务库抽数直接生成上报文件 | 直查业务库违反模块边界；转换逻辑游离于 CI 与审计之外；退回重报的版本管理与留痕缺失，不满足依法统计的可追溯要求 |
| **M19 统一加工+三级勾稽+M20 push_task 传输（选定）** | report_task 业务任务承载"待生成→已生成→已校验→已上报→已退回→已重报"全生命周期；上报数据集由指标快照+源模块统计 API 按上报表式模板（report_template 上报表式）装配；**三级勾稽**（表内：行列合计与分子≤分母；表间：同源指标跨表一致；跨期：本期期初=上期期末、累计=各期之和）通过方可上报；传输/重试/回执复用 M20 push_task 骨架（M19 为内容加工方，对齐 FU-M20-05 非职责声明）；对端退回回执驱动 RETURNED→整改→RESUBMITTED（版本递增，旧版本留痕） | 上报是全院勾稽行为，天然需要跨模块数据的单一加工点；M20 骨架复用避免传输重复建设；任务/校验/回执/退回全留痕满足卫生统计档案与数据质量责任要求 |

### 3.4 大屏/驾驶舱刷新架构：实时查询渲染 vs 全量推送 vs 缓存快照+角标推送

| 方案 | 说明 | 评估 |
| --- | --- | --- |
| 实时查询渲染 | 大屏每次刷新逐组件直查汇总库 | 多屏并发下重复聚合放大装配库压力；刷新延迟随并发不可控，难保"刷新 ≤2s"（总 Spec 8） |
| 全量服务端推送 | 全部组件经 WebSocket 持续推送 | T+1 指标推送频率无意义，连接与流量浪费；与 M14 实时大屏的推送语义混淆 |
| **缓存快照+角标推送（选定）** | 组件读 Redis 快照（指标快照装配完成即刷新缓存），页面刷新端到端 ≤2s；仅当日盘中角标（危急值未闭环数/当日质控缺陷/当日不良事件等轻量计数）经自建 `/ws/ops` 主题推送变更；REST 快照接口兜底与断连补齐 | 大屏是"数据橱窗"（调研依据 6），秒级快照读取已满足定位；角标推送限定轻量增量，避免全量重推；与 M05/M14 既有"REST 快照兜底+主题推送"模式一致 |

## 4. 领域模型

表设计统一遵循 README 第 3 节约定：雪花 BIGINT 主键、统一审计字段（created_by/created_at/updated_by/updated_at/deleted）、TIMESTAMPTZ 服务器时间、逻辑删、状态字段 VARCHAR 常量+迁移日志；金额类度量 NUMERIC(18,2) 单位元，指标值 NUMERIC(18,4)（比率类精度）。本模块无患者级表（红线 5）。

| 实体 | 关键字段 | 说明 |
| --- | --- | --- |
| indicator_definition 指标定义 | indicator_code（唯一）、indicator_name、indicator_type(ATOMIC 原子/DERIVED 派生)、calc_caliber（计算口径：分子/分母/筛选条件/精度与舍入规则的结构化描述）、dimension_set（可用维度：时间/科室/病区/院区/险别…）、period_type(日/月/季/年)、data_sources（源模块×统计 API/事件引用清单）、standard_refs（对标条目引用：国考指标号/评级条目/上报表项/核心制度监测条目）、caliber_version、release_flag（对外发布口径标记）、owner_module（责任模块）、owner_role（口径责任岗位）、status(DRAFT/PUBLISHED/DISCONTINUED) | 指标口径唯一权威（红线 3）；原子/派生两层+多口径显式建档（方案 3.2） |
| indicator_alert_rule 指标预警规则 | rule_id、indicator_ref、scope(全院/科室集)、compare_op、threshold_value、direction(高于/低于预警)、level(提醒/警告)、notify_target、enabled | 快照就绪后评估；命中发布 `ops.indicator.alerted` 并经 M01 通知 |
| ops_daily_fact 日事实宽表 | stat_date、dept_id/ward_id/campus(维度列)、原子度量列集（门诊人次/急诊人次/入院人次/出院人次/占用床日/开放床日/手术台次/各项收入分子分母[NUMERIC(18,2)]/药品·耗材收入分子等）、batch_no | 装配中间层：源模块统计 API 取数落表，指标从原子度量派生，避免逐指标重复取数；(stat_date, 维度, batch_no) 覆盖式重算幂等 |
| indicator_snapshot 指标快照 | snapshot_id、indicator_ref、caliber_version、stat_period(周期起止)、dimension_value(维度组合)、value(NUMERIC(18,4))、numerator_value/denominator_value(分子分母值，审计可溯)、source_versions(各数据源取数批次引用)、version_no、status(见第 6 节)、computed_at、frozen_at | 指标结果的唯一对外读数；被上报任务引用即 FROZEN；月/季/年快照由日快照聚合+源模块周期 API 合成 |
| report_template 报表模板 | template_code、template_name、template_type(固定报表/上报表式)、行列定义(指标 code×维度×汇总规则)、筛选参数、输出格式(表格/图表/Excel/PDF)、版式引用(M01 打印模板)、status | 综合报表与上报表式统一定义面；上报表式按卫健统/NICS 表样配置，版本化发布 |

## 5. 状态机与业务流程

- **report_task（上报任务）**：`PENDING_GENERATION(待生成) → GENERATED(已生成，数据集快照就绪) → VALIDATED(已校验，三级勾稽通过) → SUBMITTED(已上报，M20 回执 SENT 且对端受理确认) → RETURNED(已退回，对端退回回执) → RESUBMITTED(已重报，本版本终态基点)`。侧支：`GENERATED → PENDING_GENERATION`（源数据更正/上报口径调整，重新生成并留痕）；`VALIDATED → GENERATED`（上报前撤回修正）；`RETURNED → PENDING_GENERATION`（退回整改：解析退回原因→数据修正→重走生成/校验/上报，resubmit_version 递增，本轮 SUBMITTED 置 RESUBMITTED）；RESUBMITTED 后再退回则再入循环（每轮版本递增，全部版本留痕）。勾稽不通过不迁移状态（GENERATED 上挂校验失败明细，修正后重新校验）。每次迁移经状态机服务校验并留迁移日志。
- **indicator_snapshot**：`GENERATING(生成中) → READY(可用，对外读数) → FROZEN(冻结：被 report_task 生成动作引用后锁定，不可重算)`；侧支：`READY → GENERATING`（重算覆盖：仅未被任何上报任务引用的快照允许，重算记录操作者与原因）；FROZEN 永不解冻，重报场景生成新版本快照（version_no+1）走独立生命周期，旧版本永久留档。
- **report_template / dashboard_config**：`DRAFT(草稿) → PUBLISHED(发布，对外可见) → DISCONTINUED(停用：存量实例/已生成任务引用不受影响)`；模板变更以新版本发布，不修改已发布版本（与 M09 模板同思路）。
- **performance_stat**：`GENERATED(已装配) → EXPORTED(已导出对接)`；源数据更正后重装覆盖生成新版本（version_no+1），已导出版本保留可溯。

主流程时序：

1. **日终装配链（T+1 主链路）**：日终调度（以 `billing.daily-statement.closed` 就绪信号或定时双触发，以先到者为准；信号仅作触发，不作取数来源）→ 装配任务按数据源清单逐源调用统计 API（M13 收入/M03 门诊工作量/M04 住院工作量/M05/M07/M08/M09/M10/M15；M16/M17/M18 stats API 为 P6 启用接口位，启用后纳入装配清单）→ 落 ops_daily_fact 与 source_pull_log → 指标计算引擎按 indicator_definition 派生 indicator_snapshot（READY）→ 刷新 Redis 快照 → 预警规则评估（命中发 `ops.indicator.alerted` 并经 M01 通知）→ 任一源失败降级标记缺口，次日自动补拉重算。
2. **统计上报链**：统计岗创建上报任务（PENDING_GENERATION）→ 生成上报数据集快照（GENERATED，按上报表式模板装配指标快照与源 API 数据）→ 三级勾稽校验通过（VALIDATED）→ 人工审核确认 → 经 M20 push_task 传输（或导出数据包人工通道兜底）→ 回执受理（SUBMITTED，关联快照 FROZEN，发布 `ops.report.submitted`）→ 对端退回回执（RETURNED，发布 `ops.report.returned`，M01 通知统计岗）→ 整改修正→新版本快照→重新上报（RESUBMITTED，版本递增）。
3. **绩效输出链**：月度调度 → 拉取工作量（M03/M04/M05/M07/M08 统计 API、M10 手术工作量）与收入贡献（M13 收入统计快照）→ performance_stat 装配（GENERATED）→ 按绩效系统格式模板导出数据集（EXPORTED，发布 `ops.performance.exported`，导出留痕与审计）。
4. **驾驶舱刷新链**：T+1 快照装配完成刷新 Redis 快照（各视图组件读快照，刷新端到端 ≤2s）→ 当日盘中角标（消费 lab.critical-value.*、emr.qc.defect-*、nursing.adverse-event.reported 幂等累加）经 `/ws/ops` 主题推送 → REST 快照接口兜底与断连补齐。

## 7. 对外接口

- **M15**：`GET /stats/pm-completion|metrology-compliance|repair-costs|inactivity|adverse-events` 与 `GET /benefit/devices|departments|summary` 日终拉取——驾驶舱设备视图唯一数据源。
- **M16/M17/M18（P6 启用接口位，M-21 裁决采纳）**：本期在指标 data_sources 登记三者 stats API——M16 呼叫响应时长与医废重量、M17 体检人次与随访率、M18 互联网诊疗量与配送时效；三者随 M16/M17/M18 模块在 P6 交付启用（启用前接口位不产生运行时依赖），属纯只读取数登记，不改上游声明范围。
- **M14（大屏边界，无直接依赖）**：设备**运行**类实时大屏（在线率/告警/遥测吞吐/积压水位）在 M14（FU-M14-13，`/ws/iot` 端点）；M19 设备视图为**运营**视角（效益/开机率/强检/闲置，T+1 口径，经 M15 取数）。边界结论：设备"运行好不好"看 M14，设备"值不值"看 M19；web-bigscreen 前端双端点订阅（复用 M05 方案 3.5 双端点先例），两模块不重复建设同一视图。
- **M20**：上报传输骨架（push_task：打包/传输/重试/回执/留痕，M19 为内容加工方）、事件总线治理（event_registry 登记/received_event 幂等/死信）、出站留痕；本模块全部事件先登记 event_registry。
- **外部系统**：卫健统计网络直报系统/NCIS（经 M20 适配器扩展位或导出数据包人工通道）、外部绩效系统（经导出数据集对接）——均不直连业务库。
- **分析型不回写业务（红线 1）**：本模块对任何业务模块零写接口；业务更正（退费红冲/报告更正/首页修订）由源模块自治，本模块经次日凌晨重算自然收敛。

## 9. 非功能与安全

- 性能：报表查询 P95 < 2s（只读汇总库+索引）；驾驶舱/大屏刷新端到端 ≤2s（Redis 快照，总 Spec 8）；日终装配（全院全指标×科室维度）在夜间低峰 60 分钟内完成，断点重跑；上报数据集生成（年报级）≤ 30 分钟；角标事件消费 P99 < 1s。
- 可用性：驾驶舱快照持续可读（缓存层独立）；源模块统计 API 失败降级出表并显式标记缺口（对齐 M15 同款策略），次日自动补拉重算；装配任务失败可重跑且幂等；上报对端不可用时走导出数据包人工兜底通道。
- 一致性：快照重算幂等（stat_period+维度+caliber_version+version_no 覆盖）；上报快照 FROZEN 不可变；装配结果与源模块统计口径每日勾稽，差异进异常清单人工处理；指标口径变更后新旧版本快照并存可重现。
- 容量与留存：ops_daily_fact 在线 ≥3 年；indicator_snapshot ≥3 年（趋势分析）；上报数据集快照与回执原文长期留存（依法统计档案要求）；report_instance 导出文件在线 1 年后转对象存储归档；source_pull_log 在线 180 天后归档。
- 审计：指标口径变更（版本/口径卡 diff）、快照重算（操作者+原因）、上报/重报/退回处置、绩效导出、驾驶舱配置变更、手动装配触发全量审计（M01 审计切面）。
- 权限：科室维度数据范围复用 M01 数据范围（驾驶舱/报表/绩效统计按角色×范围过滤，跨范围 403 并审计）；上报操作限统计/病案统计岗独立权限点；绩效导出独立权限点+参数化审批；口径发布需指标管理员权限。
- 合规映射：全国卫生资源与医疗服务统计调查制度（依法填报、数据质量责任、勾稽校验，调研依据 2）；《医疗质量安全核心制度落实情况监测指标（2025 年版）》口径对齐（调研依据 4）；国考 55 项指标可核算性支撑（调研依据 1）；电子病历分级评价数据举证（调研依据 4/1）；等保三级（审计/权限/TLS）；个保法（本模块不落患者级明细，汇总数据天然脱敏；明细钻取实时调源模块并受源模块权限与留痕约束）。
- 时间：统计周期边界一律服务器时间（自然日/自然月），跨期勾稽以服务器时间口径衔接。

## 10. 测试要点

- 正常：日终装配链端到端（信号/定时双触发→逐源拉取→宽表落库→快照派生→缓存刷新→预警评估，各源取数批次可溯源）；卫生统计年报任务全生命周期（创建→生成→三级勾稽通过→上报→回执→SUBMITTED→关联快照 FROZEN）；退回重报闭环（退回原因解析→整改→新版本快照→RESUBMITTED→旧版本与退回原因留痕）；三视图快照数值与口径卡一致；绩效月度数据集导出格式与外部系统模板匹配；质量指标举证包导出完整。
- 边界：出院者平均住院日归属期（当日出院/跨月出院的周期切分）；分子为 0 的比率指标显示规则（不做除零，显式标注无分母）；快照被上报任务引用后重算被拦截（READY 才可重算）；口径版本切换日前后两笔快照各按旧口径版本重现；勾稽不平等三类失败（表内/表间/跨期）均阻断上报；跨期勾稽期初衔接（本期期初≠上期期末即报差异）；当日退费红冲次日凌晨重算后收入类指标收敛一致；预警阈值边界（恰好等于阈值触发方向正确）。
- 异常：源模块 API 失败→降级出表标记缺口→次日补拉重算成功；装配任务中断→断点重跑幂等（同批次覆盖不重复）；M20 传输失败→重试→FAILED→人工重推成功；重复事件投递角标不重复累加（eventId 幂等）；缓存不可用→REST 快照兜底降级；回执解析失败进人工处理清单不静默。
- 安全：跨科室数据范围查询 403 且留审计；无上报权限执行 submit 被拒；绩效导出越权（非绩效办）被拒；验证 ops schema 内无患者级表（红线 5）；导出文件访问经权限校验且下载留痕；口径修改无版本记录被拦截。
