## 1. 模块定位与边界

**职责**：本模块是互联网医院线上服务的统一入口与会话编排中枢，六项职责：① 患者端服务——注册建档（复用 M02 实人绑卡）、线上预约挂号（复用 M03 号源）、报告查询、在线缴费、投诉反馈入口的患者端编排；② 在线复诊——图文/视频问诊会话管理、复诊资格校验与合规控制（复诊判定/实人认证/处方存量校验/超范围拦截）、复诊病历（复用 M09）、处方与检查检验开立编排；③ 处方流转——电子处方对外流转单管理（定点药店/区域电子处方流转平台，经 M20 通道），药师审核复用 M06；④ 药品配送——线上购药（凭有效处方）、配送单与第三方配送商对接；⑤ 线上医保结算——医保电子凭证线上认证与医保移动支付的入口编排（资金与医保链路归 M13）；⑥ 监管上报——省级监管平台数据上报的数据集加工与上报编排（传输复用 M20 push_task）。核心资产：在线问诊会话与消息留痕、复诊资格校验记录、处方流转单与配送单、监管上报日志。

**非职责**：`visit_id` 签发与就诊业务权威（归 M03，线上复诊 visit 由 M03 签发，本模块仅编排）；处方内容权威与药师审方、药品主数据（归 M06，本模块只做开方入口编排与流转单管理，不建处方表）；复诊病历文书内容与质控（归 M09，本模块承载"书写动作发生在哪次线上就诊"的关联与医生端嵌入）；资金收退付、医保结算链路、票据（归 M13）；检验检查执行与报告（归 M07/M08，线上开单经 M03 走院内放行链路、患者到院执行）；患者身份与档案权威（归 M02）；外部协议适配与传输治理（归 M20）；药品配送商的干线运力本身（外部服务，本模块只做单据与状态跟踪）。

**模块红线**：
1. 本模块不签发任何就诊标识：线上复诊一律引用 M03 签发的 `visit_id`（类型码 `O`），就诊状态权威（接诊/诊毕/转线下登记）在 M03，本模块会话状态与之联动；禁止自建"线上就诊号"旁路。
2. 处方引用不复制：线上处方主数据与审方权威在 M06（rx_type=INTERNET），本模块只登记流转单引用与状态回执；严禁任何形式的 AI 自动生成处方与"开方前向患者提供药品"（监管细则第二十一条），开方必须由接诊医师本人经 M01 CA 电子签名完成，系统不提供批量/自动开方通道。
3. 复诊合规硬前置：会话建立前必须完成复诊资格校验（系统预检+接诊医师人工判定）与医患双端实名认证；任一环节不通过禁止进入问诊；医师判定首诊/病情变化时系统强制"终止转线下"并留档（监管细则第十八条）。
4. 金额、支付、退费动作一律调 M13 服务端完成（总 Spec 决策 D5），本模块界面金额字段不采信；线上支付引用以 `billing.settlement.completed`/`billing.refund.approved` 回执为终态权威，禁止本模块自行置"支付成功"。
5. 流转与监管对外传输一律经 M20 通道（出站留痕、接口监控、push_task），禁止本模块直连外部平台；向监管平台/流转平台/配送商提供的数据执行"最少可用原则"并脱敏（监管细则第二十五条、第二十七条）。
6. 留痕不可篡改：图文对话、音视频过程记录、复诊资格判定、处方流转状态回执全部只增留存（图文对话/音视频 ≥3 年，复诊病历按门诊电子病历 ≥15 年，监管细则第十九条）；会话消息撤回仅标记不删除。

## 2. 调研依据

1. **《互联网诊疗监管细则（试行）》（国卫办医发〔2022〕2 号）**（全文已核对）：第五条 主动与省级监管平台对接并上传执业信息；第八条 平台显著位置公布医务人员电子证照；第九条 患者知情同意；第十二/十三条 医务人员实名认证、医师接诊前实名认证确保本人服务（其他人员与人工智能不得替代）；第十四/十五条 医务人员信息（身份证号/照片/资质/执业地点等）上传监管平台并与电子化注册系统对接；第十七条 实名制、不得假冒他人就诊；第十八条 患者提供明确诊断的病历资料（门诊病历/住院病历/出院小结/诊断证明等）由接诊医师留存并判断是否符合复诊条件，病情变化/首诊/不适宜线上时立即终止并引导线下；第十九条 线上电子病历与实体机构格式一致、系统共享、线上线下一体化质控，病历记录按门诊电子病历管理保存 ≥15 年，图文对话/音视频过程记录保存 ≥3 年；第二十一条 处方由接诊医师本人开具、严禁 AI 自动生成处方、严禁开方前向患者提供药品、严禁商业目的统方；第二十二条 药品配送协议与处方流转信息可追溯并向监管平台开放数据接口；第二十三条 收费项目与标准公示；第二十五条 全程留痕可追溯、向省级监管平台开放数据接口，按"最少可用原则"采集（机构资质/人员资质/诊疗科目/病种/电子病历/电子处方/用药情况/满意度评价/患者投诉/不良事件等）；第二十七条 与合作方签订协议明确权责；第三十三条 互联网诊疗平台实施第三级及以上等保并将测评结果上传监管平台。（来源：https://www.nhc.gov.cn/yzygj/c100068/202203/2072f0e8988249e59d942e1b2a933916.shtml ）
2. **复诊范围与药品红线**：《互联网诊疗管理办法（试行）》要求不得对首诊患者开展互联网诊疗，医师可为部分常见病、慢性病复诊提供在线诊疗，不得开具麻醉药品、精神药品等特殊管理药品处方。（来源：https://www.allbrightlaw.com/SH/CN/10475/52c61aca14b56ef0.aspx ；《互联网医院服务规范》团体标准 https://dbba.sacinfo.org.cn/portal/download/a5541d53b9780f3fd1496a5212aef1082690bf923e3ad6cd2ff971bf96a00105 ）
3. **复诊预判生产实现**：《北京地区互联网医院信息系统建设指南》要求严格执行复诊条件判断，仅对既往在实体医疗机构确诊的常见病/慢性病在线复诊，需对接 HIS、EMR 等系统自动判断。（来源：http://www.phic.org.cn/zcbz/bzypj/bzgf/bjsgfxwj/202408/P020240819581532271145.pdf ）广东省人民医院互联网医院：病情稳定的慢病患者凭院内有效处方即可线上申请复诊续方、药品邮寄到家；北大医信落地方案——患者发起续方申请后系统获取院内 **3 个月内的处方记录**判断是否符合续方条件并给出提示。（来源：https://www.gdghospital.org.cn/yixun/info_itemid_71388.html ；http://www.pku-hit.com/NewsCenter/News/index/show/201/ ）
4. **线上处方量法规口径**：《长期处方管理规范（试行）》（国家卫健委办公厅、国家医保局办公室）——长期处方量一般 4 周内，慢性病病情稳定可适当延长、最长不超过 12 周。（来源：https://www.nhsa.gov.cn/art/2021/8/13/art_37_5778.html ）
5. **处方流转生产模式**：深圳电子处方中心对接实体医疗机构、互联网医院、零售药店、处方药销售平台、医保信息平台、支付结算机构，实现处方流转与药店同等医保统筹报销；国家医保局"医院外配处方如何流转到药店"——处方经平台流转至院外定点零售药店的电子化、规范化管理；2025-01-01 起"双通道"药品定点零售药店均需通过电子处方中心流转处方、不再接受纸质处方；院内流转与院外流转（药店自取/O2O 配送）双模式为行业通行形态。（来源：https://wjw.sz.gov.cn/jyzx/xxgk/gzdt/content/post_12593990.html ；https://www.nhsa.gov.cn/art/2025/7/14/art_14_17246.html ；https://www.chinanews.com.cn/jk/2025/01-21/10357009.shtml ）
6. **线上医保结算**：《医疗保障信息平台便民服务相关技术规范》规定医保码、医保移动支付、医保电子处方、个人医保信息授权查询 4 项便民服务的接入功能、接入方式、安全和管理要求；医保电子凭证由国家医保信息平台统一签发、实名/实人认证；深圳已将互联网定点机构慢病复诊记账费用纳入线下医保结算范围、线上复诊人次纳入门诊人次计算。（来源：https://www.nhsa.gov.cn/module/download/downfile.jsp?classid=0&filename=87f1da7d06414420926bb75c859f9334.pdf ；https://hsa.sz.gov.cn/zwgk/zcfgjzcjd/zcfg/ylbx/content/post_7259119.html ）
7. **监管平台对接形态**：省级监管平台对互联网诊疗实施事前、事中、事后全流程监管（东软集团互联网医院监管平台解决方案，见其官网医疗卫生板块产品页 neusoft.com）；"北京模式"要求互联网医院接入监管平台、医疗服务与执业监管数据经接口实时上传；各地要求按《互联网医疗服务监管平台数据接口规范》完成接口改造达到实时监管标准后方可开展服务。（来源：http://www.cn-healthcare.com/api/third/article/550088 ；https://wsjkw.hebei.gov.cn/tzgg/372743.jhtml ）
8. **问诊媒体服务**：主流互联网医院以图文、音视频建立医患线上沟通并实时共享病历资料（网易云信智慧医院方案、腾讯健康智慧医院信息服务），媒体通道普遍采用第三方音视频云服务，医疗业务方保留会话编排与留痕。（来源：https://yunxin.163.com/medhos ；https://yl.tencent.com/docs/100003 ）

## 3. 方案推导（关键设计点选型）

### 3.1 线上就诊与院内 visit 的关系：独立线上就诊号 vs 不建 visit 仅会话 vs 复用 M03 visit_id（O 型 + 线上渠道标记）

| 方案 | 说明 | 评估 |
| --- | --- | --- |
| 新设线上 visit_id 类型码（如 `V`）由本模块签发 | 线上线下标识分立 | 与 M02 visit_id 结构规范"门诊由 M03 唯一签发（类型码 O）、其余模块不得签发"的既定契约冲突；线上线下一体化病历（细则第十九条"格式一致、系统共享"）、处方、收费语义被人为割裂，M09 病历、M13 结算清单、M19 统计需双轨适配 |
| 不建 visit、仅以会话为业务锚 | 会话即诊疗 | 复诊病历（M09 挂 visit）、线上处方（M06 处方挂 visit_id）、检查检验开单（M03 clinic_order 挂 visit）、医保结算（M13 费用挂 visit）全部失去业务锚点；监管上报要求电子病历/电子处方可追溯至就诊，无 visit 不可行 |
| **复用 M03 visit_id + 线上渠道标记（选定）** | 线上复诊 visit 由 M03 签发（类型码 `O`，与线下同构），visit_type 取"互联网诊疗"（国卫办医政发〔2024〕16 号门诊诊疗信息页就诊类型代码 4），渠道标记为线上；本模块只做"会话 ↔ visit"的 1:1 关联编排 | 满足"线上线下一体化"（细则第十九条 + 国家医保局"五个一"要求互联网医院与实体机构数据共享、线上线下无缝衔接，调研依据 6/8）：病历、处方、费用、统计天然同构；M03 Spec 已声明"M18 复用本模块号源与预约服务、患者端经 M18 入口业务落 M03"，本方案是该契约的落地；职责结论：**就诊业务权威在 M03，本模块承载线上交互与会话编排**——接诊/诊毕动作由本模块医生端发起、落 M03 visit 状态 |

**结论**：复用 M03 visit_id（O 型）+ visit_type=互联网诊疗（代码 4）+ 渠道标记线上。与 M03 的契约：① 线上入口两条——预约式（经 M03 号源池"互联网复诊"专用号别预约，到点取号签发 visit）与快速图文（申请时按当日号直接挂号签发 visit）；② 会话建立时本模块调 M03 预约/挂号 API 并回填 visit_id，一次线上 visit 对应一个会话（唯一约束）；③ 接诊/诊毕经 M03 `POST /visits/{visitId}/admit|finish` 驱动 visit 状态，诊毕离院去向按国标代码记录；④ 转线下 = 本模块终止会话（visit 置终态），患者到院按 M03 正常线下流程重新挂号，两个 visit 在会话记录中登记转诊关联；⑤ 线上检查/检验/治疗开单调 M03 开单 API（开单编排权威在 M03），计费与放行走 M03→M13→M07/M08 既有链路。

### 3.2 复诊合规控制链：单点人工判定 vs 纯规则自动拦截 vs 系统预检 + 医师人工判定 + 实人认证 + 处方存量校验的四重防线

| 方案 | 说明 | 评估 |
| --- | --- | --- |
| 单点人工判定 | 只靠接诊医师判断是否复诊 | 合规上医师判定是法定必要环节（细则第十八条），但无系统预检则首诊/超期申请直达医师，浪费接诊资源且判定依据不结构化、留痕弱；事后监管举证困难 |
| 纯规则自动拦截 | 规则命中即放行/拒绝，医师只签字 | 规则只能证明"有历史记录"，不能替代医师对"病情是否稳定、是否适宜线上"的专业判断；自动放行违背细则"由接诊医师判断"的立法本意，审计风险高 |
| **四重防线（选定）** | ① **系统预检**（可自动判定的硬条件）：本院就诊史校验（近 N 个月[参数化，默认 3 个月]内同科室/同诊断有确诊就诊或有效处方，经 M03/M06 取数 API，对齐北京建设指南"HIS/EMR 自动判断"与广东省医"3 个月内处方记录"生产实践）；外院资料通道（患者上传门诊病历/出院小结/诊断证明等，医师接收后转 M09 归入复诊病历附件留存）；② **医师人工判定**（法定终审）：接诊医师对照资料判定复诊条件，结论与理由落 recheck_record；③ **实人认证**（双端时点）：患者注册建档绑卡人脸核身（M02）+ 每次接诊前人脸核身（细则第十七条实名制）+ 视频接通活体检测（媒体服务能力位）；医师接诊前实名认证（M01 账号 + 执业授权 + 电子证照公示，细则第八/十二/十三条）；④ **处方存量与范围校验**（续方场景）：近 3 个月内有相同诊断有效处方方可续方（生产实践，调研依据 3）；续方量受长期处方规范约束（一般 4 周、慢病稳定最长 12 周，调研依据 4）；麻精等特殊管理药品开方拦截（M06 药品字典毒麻类别 + 细则第二十一条）；医师判定首诊/病情变化时强制"终止转线下"并必填原因 | 硬条件自动化减少无效申请，专业判断保留给人，合规与体验兼得；每个环节独立留痕（recheck_record + 会话留痕），满足第二十五条"全程留痕可追溯"的监管举证；参数化窗口（3 个月）随属地监管口径可调 |

**结论**：四重防线。配套：候诊超时（参数化）经 `fy.delay` 自动关闭会话并退号；医师接诊容量上限控制（防超负荷接诊）；投诉入口与满意度评价在会话结束后开放（细则第二十五/二十九条数据集与反馈渠道要求）。

### 3.3 处方流转架构：M18 自建流转通道 vs 复用 M06 处方 + M18 流转单 + M20 通道（含配送与回执闭环）vs 全委托第三方平台

| 方案 | 说明 | 评估 |
| --- | --- | --- |
| 本模块自建对药店/平台的全部协议通道 | 端到端自研 | 出站协议、留痕、监控、重试与 M20 既有能力重复建设；对端增多后通道治理失控，违反 M20"一切对外协议经通道"红线 |
| **M06 处方权威 + M18 流转单 + M20 通道（选定）** | 线上处方在 M06 开立（rx_type=INTERNET，审方引擎复用：预检 + 药师复审，审方通过发布 `pharmacy.prescription.created` 携药品计费行）→ 本模块按患者选择建 online_prescription_ref 流转单（目标：院内取药 / 定点药店自取 / 流转平台或药店配送到家）→ 经 M20 通道推送电子处方（加密、CA 签名验签、追溯信息）→ 目标方状态回执（已接收/已配药/已配送/已签收/已退回）回流驱动流转单状态机 → 每日与目标方对账 | 职责清晰：处方内容与审方权威仍在 M06（其 Spec"互联网处方经 rx_type=INTERNET 复用审方引擎"预留的激活），本模块只管"流转单"这一流转域单据；通道治理、留痕、监控、幂等全部复用 M20；处方流转信息可追溯并向监管平台开放（细则第二十二条）直接由流转单状态机 + M20 留痕支撑 |
| 全委托第三方互联网医院平台 | 处方流转整体外包 | 处方数据出域失控、审计不可达；与院内 M06/M13 闭环割裂；合规责任无法外包（细则第三十四条法律责任在机构） |

**结论**：M06 处方权威 + M18 流转单 + M20 通道。费用规则：目标=院内取药/院内邮寄 → 患者线上缴药费（M13）→ `billing.settlement.completed` → 既有 M03 扇出 → M06 院内发药管线（邮寄场景发药后生成 delivery_order 委托第三方承运）；目标=定点药店/流转平台 → 院内药费 PENDING 费用作废（未结算，M13 API）、药费在药店端结算（含医保"双通道"药品必须经电子处方中心流转，调研依据 5），本模块只跟踪流转状态。放行硬条件 = 审方通过 ∧（院内场景已缴费；外配场景流转受理回执）。配送：第三方配送商（细则第二十二条允许自行或委托第三方，协议与流转信息可追溯），配送单全程状态回执，配送商不可用时转人工派单。

### 3.4 视频问诊媒体服务边界：自建 WebRTC/SFU vs 全托管第三方音视频云（接口位预留）

| 方案 | 说明 | 评估 |
| --- | --- | --- |
| 自建 WebRTC/SFU 媒体服务器 | 音视频信令、转码、录制全自建 | 媒体基础设施（全球加速、弱网对抗、多端适配）非医院 IT 长项，建设与运维成本高；等保测评面扩大；总 Spec 既有先例（PACS 高级后处理、IoT 平台）均"主干自建 + 标准能力集成" |
| **第三方音视频云 + 适配器接口位（选定）** | 信令与会话编排在本模块（何时邀请、接通、挂断、超时），媒体通道（音视频流、活体检测、云端混流录制）由可配置的第三方服务承载（网易云信/腾讯健康/华为云会议类，调研依据 8）；录制件加密回存本模块对象存储（≥3 年，细则第十九条）；信令事件（邀请/接通/中断/时长）落 consult_message 留痕 | 媒体能力开箱即用、弱网体验有 SLA 保障；供应商可替换（适配器隔离）；录制件归属院内满足留痕合规；本模块保持会话编排权威，不因换供应商改造业务 |
| 降级策略 | — | 媒体服务不可用时视频会话显式降级为图文（告知患者），不中断问诊服务 |

**结论**：第三方音视频云 + 适配器接口位 + 录制件院内归档。图文消息通道为自建（本模块 WebSocket，见第 7 节），仅音视频媒体面走第三方。

### 3.5 线上医保结算路径：本模块直连医保平台 vs 复用 M13 医保链路 + 医保移动支付编排

| 方案 | 说明 | 评估 |
| --- | --- | --- |
| 本模块直连属地医保/国家医保移动支付中心 | 独立对接 | 与 M13 红线"医保出站统一经 M20 通道、结算逻辑收口 M13"冲突；预结算/冲正/对账能力重复建设；线上线下结算口径漂移 |
| **复用 M13 + 本模块只做编排（选定）** | 患者端发起线上缴费 → 本模块建 online_payment_ref（业务类型：挂号费/诊查费/药费/检查检验费）→ 调 M13 收银台 API（预结算/结算）：医保患者经医保电子凭证线上认证与医保移动支付中心通道（接入规范见调研依据 6，通道在 M13/M20），自费走聚合支付；`billing.settlement.completed` 回执驱动本模块放行（流转/配送/报告已缴标记）；退费消费 `billing.refund.approved` 后原路退回 | 线上线下同一结算权威与对账口径（深圳实践：互联网复诊纳入线下医保结算范围，调研依据 6）；本模块零资金逻辑（红线 4）；支付超时经 `fy.delay` 自动关闭并释放占用 |

**结论**：复用 M13 + 编排在本模块。线上医保结算范围以属地医保开通情况为前提，未开通线上统筹的费用显式提示转自费或线下结算（参数化开关）。

## 5. 状态机与业务流程

- **online_consultation 会话**：`WAITING（候诊：复诊申请与资料提交、资格预检通过、visit 已签发）→ ACCEPTED（已接诊：医师实名认证后接诊，患者侧接诊前人脸核身通过）→ IN_CONSULT（问诊中：图文/视频交互）⇄ PRESCRIBED（已开方：处方生效待缴费流转，可继续问诊调整）→ FINISHED（已结束：诊毕，调用 M03 诊毕并记录离院去向，开放满意度评价）`；`WAITING → CANCELLED（患者取消/资格不通过/候诊超时自动关闭，退挂号费联动 M13）`；`ACCEPTED/IN_CONSULT/PRESCRIBED → FINISHED（转线下：OFFLINE，终止原因必填留档，引导线下挂号）`；`ACCEPTED 后超时候诊（医师接诊后长时间未进入问诊）→ FINISHED（finish_type=TIMEOUT，R5-14）`；两类超时均经延迟队列自动触发（参数化）——候诊超时（WAITING）视为未接诊走取消退费、接诊后超时候诊以 TIMEOUT 结束，二者不再混用同一出口。迁移经状态机服务校验并留日志；FINISHED 前置校验：在途流转单均已进入终态或经医师显式确认。
- **online_prescription_ref 流转单**：`PENDING_FLOW（待流转：处方已生效，院内场景待缴费）→ FLOWED（已流转：电子处方已推送目标并获受理回执）→ ACCEPTED（已接收：药店/平台确认接收，外配药费在药店端结算）→ DISPENSED（已配药）→ DELIVERED（已配送：院内邮寄/平台到家出库承运）→ SIGNED（已签收，终态）`；`ACCEPTED 之后 → RETURNED（已退回：含退回原因，院内场景触发 M13 退费审批、外配场景登记并向监管留痕）`；`PENDING_FLOW → CANCELLED（处方作废联动 M06）`。
- **delivery_order 配送单**：`CREATED（已创建待揽收）→ PICKED_UP（已揽收）→ IN_TRANSIT（运输中）→ DELIVERED（已妥投）→ SIGNED（已签收确认，终态）`；`PICKED_UP/IN_TRANSIT → FAILED（配送失败：转重新派单或退回原处方流转单 RETURNED）`；退回件回流经 M06 批次管理，本模块只登记状态。
- **online_payment_ref**：`PENDING（待支付，占位时限参数化）→ PAID（已支付，billing.settlement.completed）`；`PENDING → CLOSED（超时关闭/取消）`；`PAID → REFUNDED（已退费，billing.refund.approved）`。
- **recheck_record**：`SUBMITTED（申请已提交）→ PRECHECKED（系统预检完成：通过/不通过）→ JUDGED（医师判定完成，终态：QUALIFIED 复诊资格确认 / REJECTED 不予线上复诊并引导线下）`。
- **regulatory_report_log**：`PENDING（数据集就绪待上报）→ SENT（已提交监管平台）→ ACKED（回执确认，终态）/ FAILED（回执失败或超时，人工处置后重推）`。

主流程时序：

1. **在线复诊主链路（图文/视频）**：患者端登录（M02 实人）→ 提交复诊申请（病情描述+资料，recheck_record=SUBMITTED）→ 系统预检（本院 3 个月内就诊史/处方存量，调 M03/M06 取数 API）→ 预检通过建会话（预约式经 M03 号源取号签发 visit；快速图文直接挂号签发 visit）→ 患者候诊（online_duty 容量控制，候诊提醒经 M01 通知中心）→ 医师实名认证后接诊（`POST /visits/{visitId}/admit`，患者接诊前人脸核身）→ 问诊中（图文经 WebSocket 实时收发留痕；视频经媒体适配器接通，录制件回存）→ 开检查/检验/治疗单（调 M03 开单 API，患者线上缴费后到院执行走 M03 既有放行链路）→ 开处方（调 M06 开方 API，rx_type=INTERNET，执业授权强校验 + 审方预检 + 药师复审）→ `pharmacy.prescription.created`（携药费计费行，M13 生成 PENDING）→ 患者选择院内取药/邮寄/外配 → 诊毕（校验在途单据，调 M03 诊毕）→ `internet.consultation.finished` → 满意度评价。
2. **处方流转与配送链**：处方生效后患者选定流转目标 → 建 online_prescription_ref：院内场景线上缴药费（M13）→ settlement.completed → M03 扇出放行 → M06 发药/邮寄（邮寄生成 delivery_order）；外配场景调 M13 作废院内药费 PENDING → 经 M20 通道推送电子处方 → 受理回执 → FLOWED/ACCEPTED → 药店配药回执 DISPENSED → 平台到家出库 DELIVERED → 配送单跟踪 → 签收 SIGNED → `internet.prescription.signed`；任一环节退回 → RETURNED → 院内场景 `billing.refund.approved` 后退费闭环 → 流转状态回执与对账数据同步供监管上报（细则第二十二条）。
3. **线上医保结算**：患者端发起缴费 → online_payment_ref=PENDING → 调 M13 收银台（医保电子凭证线上认证 → 预结算 → 医保移动支付/自费支付 → 正式结算）→ `billing.settlement.completed` → PAID + 放行 → 超时经延迟队列自动关闭；退费申请经 M13 分级审批 → `billing.refund.approved` → REFUNDED + 业务逆向（会话取消/流转单退回）。
4. **监管上报**：按数据集类型（第二十五条清单）定时/事件驱动加工数据集 → 登记 regulatory_report_log → 复用 M20 push_task 推送省级监管平台 → 回执 ACKED/FAILED → 失败人工重推；机构与人员资质信息按第五/十四/三十三条定期上传（含等保测评结果）。
5. **转线下**：问诊中医师判定首诊/病情变化/不适宜线上 → 强制终止（termination_reason 必填）→ 会话 FINISHED（OFFLINE）→ visit 诊毕登记 → 患者端推送线下就诊引导（科室/号源直达入口）→ 转诊关联留档。

## 8. 集成点

- **M01**：认证与 RBAC（患者端匿名仅公开信息，问诊/开方/流转/上报独立权限点；医生端复用员工账号体系）；执业授权强校验（线上开方前调 `POST /api/v1/system/practice/check`，含处方权/抗菌药分级）；CA 电子签名（处方签名、复诊病历签名、知情同意签署）；字典与系统参数（复诊有效期窗口/接诊容量/超时阈值/支付时限/监管数据集口径，全部参数化）；通知中心（候诊/报告/配送/取药提醒与投诉流转）；审计切面（接诊、终止转线下、开方、流转目标变更、上报重推全量审计）。
- **M02**：注册建档与实人绑卡（人脸核身经其介质核验适配器）；接诊前患者人脸核身调其实人认证服务并留存认证凭据摘要；就诊人管理与监护人代管授权；患者合并（`patient.merged`）后会话/流转/支付读侧经 EMPI 归一；脱敏与明文查阅规则全端生效。
- **M03（visit 与开单契约，双向对齐其 Spec 第 8 节）**：① 业务权威在 M03：线上 visit 由 M03 签发（类型码 `O`，visit_type=互联网诊疗/信息页代码 4，渠道标记线上），本模块为线上入口与编排方，不签发任何就诊标识；② 预约挂号/当日挂号/取号复用其号源服务与预约 API（互联网复诊专用号别入号源池统一管理）；③ 接诊/诊毕动作经其 API 落 visit 状态（含转线下的诊毕登记）；④ 线上检查/检验/治疗开单调其开单 API，计费与执行放行走 M03→M13→M07/M08 既有链路，患者到院执行；⑤ 本模块消费其 visit 事件做会话联动。统一审查对照点：M03 Spec visit_type 枚举需按信息页代码补齐"互联网诊疗"取值（M03 调研依据 1 已含该代码）。
- **M06（处方与审方契约，双向对齐其 Spec 第 8 节 M18 条目）**：① 线上处方经其开方 API 开立（rx_type=INTERNET，该"预留"由本模块激活），处方主数据与药师审方权威在 M06，本模块红线 2 不复制处方明细；② `pharmacy.prescription.created` 携药品计费行 → M13 生成 PENDING 费用（与门诊同构，杜绝未审先费）；③ 处方流转对外接口在其 Spec 为预留位，本模块为流转域单据（online_prescription_ref）权威，外发动作经 M20；④ 院内取药/邮寄复用其门诊发药管线与退药回收（追溯码核验）。
- **M09**：复诊病历文书复用其文书模型与编辑器组件（线上 visit 上下文适配位激活，visit_scope=OUTPATIENT 口径管理）；外院复诊资料经医师确认后归入病历附件；线上病历纳入其线上线下一体化质控；患者端报告/病历调阅经其查询 API + M02 授权脱敏边界输出。
- **M13（资金与医保契约，双向对齐其 Spec 第 8 节"线上缴费/线上医保结算复用"）**：① 线上缴费统一调其收银台 API（预结算/结算/退费），医保电子凭证线上认证与医保移动支付通道在其与 M20；② PENDING 费用来源于 M06 处方事件与本模块经 M03 的开单事件，本模块零资金逻辑；③ 外配场景未缴费药费经其作废 API 联动；④ 结算/退费回执事件驱动本模块支付引用与放行终态。
- **M07/M08**：报告发布事件驱动患者端提醒；报告查询经其 API；线上开单的执行与报告仍走院内闭环，本模块不做医技执行。
- **M20**：处方流转（药店/电子处方中心）、监管上报（省级监管平台）、配送商、媒体服务的对外传输统一经其通道（interface_channel 配置 + interface_call_log 留痕监控）；监管上报复用 push_task 骨架（其 FU-M20-05 已声明 M18 复用）；事件信封/幂等构件/延迟队列（`delay.consult-timeout` 候诊超时、`delay.pay-deadline` 支付时限、`delay.report-retry` 上报重试）；本模块全部事件先登记 event_registry。
- **外部对端（均经 M20，不直连）**：省级监管平台（第五/二十五条数据接口）、定点药店/区域电子处方流转平台、第三方配送商、音视频云服务商（协议与权责按第二十七条签订并留档）。
- **M19**：互联网诊疗工作量（会话量/视频占比/转线下率）、处方流转量与配送时效、满意度统计取数 API（只读）。

## 9. 非功能与安全

- 性能：图文消息端到端（发送→对端收到）≤1s；视频接通时长 ≤5s（依赖第三方媒体服务 SLA，适配器内探活）；候诊队列状态推送 ≤2s；患者端核心接口（申请/查询/缴费发起）P95 < 500ms；监管数据集批量加工在夜间低峰完成，实时增量上报延迟 ≤5 分钟。
- 容量：按 P2 阶段日均数百单复诊、峰值并发视频 50 路规划；媒体带宽与并发由第三方服务弹性承载，本模块仅承载信令与业务（会话峰值并发 500 级）。
- 可用性：问诊服务 7×24（线上服务窗口参数化可配）；第三方媒体服务不可用 → 视频降级图文（显式告知患者，会话不中断）；监管平台/流转平台不可用 → push_task/通道按退避重试，失败转人工重推，不阻断院内问诊；M13 不可用时缴费受影响显式提示，问诊与开方可继续（费用 PENDING 事件积压重放）。
- 一致性：会话与 visit 状态以 M03 事件为权威校正；支付引用以 M13 回执为权威；流转单状态以目标方回执为权威（本地预置状态仅乐观展示）；事件发布走 outbox（M20 治理约定）；每日三类对账——支付引用↔M13 结算单、流转单↔目标方回执、上报日志↔监管回执，差异进异常工作台。
- 审计：接诊、终止转线下（原因必填）、开方、复诊判定、流转目标变更、上报重推、投诉处置全量审计（M01 切面）；医师线上接诊行为（上线/接诊/结束）独立留痕供医务考核（细则第十四条考核机制的数据源）。
- 合规映射：等保三级且测评结果上传监管平台（细则第三十三条）；实名制双端认证（第十二/十三/十七条）；复诊判定与终止转线下（第十八条）；病历 ≥15 年、图文对话/音视频 ≥3 年（第十九条）；处方红线（第二十一条：本人开具/禁 AI 生成/禁开方前供药/禁商业统方——统方类查询功能不提供，处方数据访问最小化）；流转信息可追溯（第二十二条）；收费公示（第二十三条）；全程留痕可追溯与最少可用上报（第二十五条）；合作方协议权责（第二十七条）；数据出域管控——向监管平台/流转平台/配送商提供的数据一律按数据集口径最小化、患者标识脱敏或按对端规范伪码化、出站全留痕、禁止原始明细批量导出；敏感字段（证件号/手机号/地址/收货人）存储加密。
- 数据留存：会话消息与音视频留痕 ≥3 年、复诊病历及附件 ≥15 年（随 M09 病历管理）、流转单与配送单 ≥5 年（医保核查窗口叠加追溯要求）、监管上报日志与回执长期保留；录制件加密存储于对象存储并纳入生命周期分层（在线 1 年 → 归档至 3 年期满）。

## 10. 测试要点

- 正常：在线复诊全链路（申请→预检→建会话签发 visit→候诊→双端实名→接诊→图文/视频问诊→开检查检验单→开方审方→缴费→流转/配送→签收→诊毕→评价），逐步核对会话状态、visit 状态、事件与留痕；复诊病历在 M09 生成且与线下门诊病历同构（信息页含就诊类型=互联网诊疗）；处方流转到药店全回执链（受理→配药→配送→签收）；院内邮寄链（M06 发药→配送单→签收）；线上医保结算（认证→预结算→移动支付→结算→放行）与自费结算双路径；监管数据集九类内容逐项上报并获得回执 ACKED；转线下流程（终止原因留档→线下挂号引导）。
- 边界：预检恰好 3 个月边界（第 90 天就诊史有效/第 91 天拦截，参数可调）；续方处方存量校验在多处方并存时取相同诊断最近一张；接诊容量满时申请进入排队而非拒绝；候诊超时自动关闭与患者缴费成功并发（先到先得，不双占）；外配场景院内药费作废仅限未结算（已缴费场景强制走院内发货或退费）；转线下后原 visit 禁止再产生任何线上开单与开方；麻精药品在线上开方界面不可见且 API 层拦截；AI 自动开方通道不存在（代码路径与权限点审计验证）。
- 异常：`billing.settlement.completed` 重复投递仅放行一次（幂等）；`pharmacy.prescription.rejected` 后流转单不可创建、医生端收到驳回意见；目标方受理回执超时未达 → 对账任务发现并人工补偿；配送失败转重新派单或退回后退费闭环完整；媒体服务中断 → 视频降级图文且信令留痕完整；监管平台回执失败 → push_task 重试耗尽转人工、重推成功后日志 ACKED 且不重复上报（幂等）；`patient.merged` 后历史会话/处方/支付读侧归一到主档。
- 安全：未通过人脸核身的患者无法进入接诊（会话拦截并留痕）；医师停权（practice.changed）后在线状态自动离线且不可接诊；无权限角色调用流转/上报接口 403 且留审计；日志与事件载荷中患者敏感字段脱敏抽验；向监管平台数据集仅含"最少可用"字段（对照清单逐项核验）；录制件访问独立权限点 + 查阅留痕；投诉与处方数据查询无统方口径导出。

## 12. 与总 Spec 的偏差

无结构性偏差。四处细化澄清（已经统一审查裁决确认）：
1. **M03 visit_type 枚举补齐**：本模块按国卫办医政发〔2024〕16 号门诊诊疗信息页就诊类型代码 4 复用 M03 visit（O 型）承载线上就诊——**M03 v1.1 已按 R2-08 在 §4 visit_type 枚举补齐"互联网诊疗"取值（信息页代码 4）与线上渠道标记，本项闭环（90 号文档备案终审 #12）**。号别表达裁决请求（R5-16）：采用"复诊号别+线上渠道配额"——线上号源容量复用 M03 现有 channel_quota_rule 的线上渠道配额表达（互联网复诊专用号别入号源池统一管理），不扩展号别枚举。
2. **M06 rx_type=INTERNET 激活**：M06 Spec 将互联网处方列为"预留（本期不实现）"，本 Spec 在 P2 阶段启用该处方类型并复用其审方引擎与开方 API；事件名经逐一比对与 M06 登记一致，最终以 event_registry 登记为准（R5-15），无新增 M06 接口。
3. **M09 线上 visit 上下文适配位激活**：M09 Spec 预留"线上就诊 visit 上下文与类型由 M18 Spec 定义"，本 Spec 定义为——线上复诊病历按 OUTPATIENT 口径（门诊电子病历，≥15 年）挂 M03 O 型 visit，编辑器组件复用；请审查确认 M09 质控规则覆盖线上病历。
4. **FU-M18-01 职责口径**：患者端服务中的预约挂号/报告查询/在线缴费为入口编排能力（业务权威分别在 M03/M07/M08/M09/M13），本模块不自建号源、费用与医技逻辑；与 M03/M13 Spec 第 8 节"M18 复用"声明互为印证，属职责切分澄清而非功能增减。
