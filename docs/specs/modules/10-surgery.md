## 1. 模块定位与边界

**职责**：本模块是围术期医疗业务的权威中枢，八项职责：① 手术申请与排班——受理住院手术医嘱（M04 分发）、手术室/台次排程与变更、冲突检测、急诊插台；② 术前管理——术前访视与评估（ASA 分级、气道与风险要素、身高体重/BMI）、术前准备核查单、手术与麻醉知情同意签署登记；③ 手术安全核查——麻醉实施前/手术开始前/患者离室前三方电子核查单，时序门控强制推进；④ 麻醉记录单——按国家强制性标准《麻醉记录单标准》（WS 329-2024）建模的电子麻醉记录，术中监测数据自动采集（引用 M14 遥测）、事件标注（给药/输液/输血/插拔管/体位）、定稿快照固化；⑤ 器械敷料清点——与手术关联的四时点双人清点单、双签确认、数目不符应急处置与离室锁定；⑥ 术后管理——PACU 复苏记录（麻醉后恢复评分）、术后镇痛（PCA）管理、术后随访；⑦ 手术计费衔接——手术开始/结束事件驱动 M13 计价、术中耗材扫码计费行登记、术式↔收费项目对照；⑧ 手术室大屏——手术进度公示与手术间运行态势。核心资产：手术申请/围术期流程状态机（核查门控硬约束的载体）、手术结构化记录主档（M09 首页手术行与手术记录文书的权威数据源）、麻醉记录单（随病历长期保存的法律文书）、清点单与核查单（手术安全追溯凭证）。

**非职责**：手术医嘱的开立/审核/状态权威（归 M04，本模块只消费分发事件并回执聚合）；手术记录文书本身（术者术后 24h 内书写，归 M09；手术结构化信息——术式/术者/起止时间/切口等级——以本模块事件与查询为权威源，M09 Spec 边界结论一致）；病历通用编辑器、质控引擎与病案首页装配动作（归 M09，本模块只提供手术行数据）；毒麻精放的专册登记、双人双锁授权与库存账（归 M06，本模块只发起借用/退回/空安瓿核销请求并保存借用单号引用，术中给药事实记录在本模块麻醉记录单）；计价规则、收费与退费权威（归 M13，本模块只发计费事件与转调）；术前准备类护理任务执行（备皮/导尿/配血执行归 M05，本模块只消费执行回执做就绪判定）；患者回病区后的术后护理记录（归 M05）；术后转入 ICU 的重症监护记录（归 M11）；术中输血医嘱与床旁执行闭环（归 M12，本模块麻醉记录单按 WS 329 要求做输血事件标注并引用其输血单号）；设备资产台账、计量检定、维修保养与效益分析（归 M15，本模块只引用设备标识并输出使用事实）；器械包清洗灭菌与消毒供应追溯（院外 CSSD 系统职责，本模块只引用器械包标识）；遥测解析、落库、设备绑定判定（归 M14，本模块只查询与消费事件）。

**模块红线**：
1. 围术期流程状态机是手术全流程推进的唯一权威：状态迁移必须经状态机服务校验并留迁移日志（README 约定）；核查、清点、毒麻闭环等前置条件为**服务端硬门控**——任一门控未满足，状态不得推进，不得以提醒代替拦截；急诊抢救例外放行必须双人授权+原因留痕+事后审查。
2. 麻醉记录单定稿（FINALIZED）后即固化只读：监测数据快照不再随 M14 遥测保留策略（明细 90 天）变化而失真；定稿后修订走留痕版本链且原值可见（对齐电子病历规范与 WS 329-2024 5.8"已录入打印并签名的麻醉记录单不得修改"）；麻醉记录单随病历保存 ≥30 年。
3. 麻醉用药只记"给药事实"（药品+批号+剂量+途径+时间+给药人），不建任何药品库存账；毒麻药品的借用/退回/核销登记权威在 M06 专册，本模块保存借用单号与批号引用并保证给药事件可按批号追溯；毒麻借用单未闭环（未核销且未退回）不得置手术完成。
4. 计费只发事件与转调 M13：本模块不写任何费用表、不存价格（总 Spec 决策 D5）；计费行 item_code 引用 M13 收费项目，术式↔收费项目对照为本模块专业映射表（非价格副本）。
5. 禁止跨模块读表：遥测经 M14 查询接口、执业授权与手术分级调 M01 校验接口、过敏史与健康档案调 M02、医嘱状态以 M04 事件与接口为准；本模块对外仅暴露 API 与事件。

## 2. 调研依据

1. **手术麻醉信息系统（AIS/AIMS）全流程生产形态**：覆盖入院→术前→术中→术后→出院全过程，与 HIS/LIS/PACS/EMR 信息共享，分术前（申请/排班/访视/评估/知情同意）、术中（麻醉记录自动采集、事件记录、器械清点、计费）、术后（复苏 PACU、镇痛、随访、归档）三阶段；主流厂商（创业慧康、易软、大平、迈瑞等）功能清单高度一致，普遍含麻醉大屏、病案归档与麻醉质控统计；国家卫健委《医院麻醉科建设与管理指南（试行）》明确"有条件的三级医院可建立电子麻醉信息系统，包括术前访视评估、术中记录、术后随访信息"。（来源：https://baike.baidu.com/item/手术麻醉信息系统/9557204 ；https://www.yilutong.net/xinwendongtai/xingyexinwen/487.html ；http://www.nhc.gov.cn/yzygj/s3593y/201304/4b3f0050ed234287be45a0416b319f9b.shtml ）
2. **《麻醉记录单标准》WS 329-2024（强制性卫生行业标准，2025-08-01 起实施，代替 WS 329-2011）**——本模块麻醉记录单建模的直接法定依据，全文要点：麻醉开始=患者入室执行基本生命体征监测和/或治疗医嘱，麻醉结束=达到出室标准和/或移交其他科室医师/护士（3.2/3.3）；患者一般信息含姓名/性别/年龄书写规则/身高/体重/**身体质量指数 BMI（新增，6.2.6）**/科别/病房/病历号/时间精确到分/页码（多次麻醉每次独立编页）；术前情况含 **ASA 分级（附录 A，成人/小儿/产妇分列评估，急诊在分级后加"E"）**、手术类型（急诊/择期）、术前禁食、麻醉前用药（精确到分）、术前特殊情况、术前诊断与拟施手术（与手术同意书一致）、手术体位；术中情况含手术方式（由手术者口述、麻醉医师记录）、手术医师/麻醉医师/**麻醉护士（新增）**/巡回护士、用药（剂量/途径；连续泵入记录起止时间与浓度及变化）、**术中监测**（全麻持续记录吸入氧浓度；所有麻醉方式持续记录血液氧合且**至少每 15min 记录一次**；机械通气记录设定呼吸参数且调整时重记、呼出气二氧化碳**至少每 30min 记录一次**；连续监测心电图；**脉搏和血压至少每 5min 记录一次**；预计手术长于 120min 者监测体温且至少记录一次；扩展监测可选）；静脉输液与输血（名称/量/时间、血型、自体血回输、不良反应）；标记（重要麻醉/手术步骤、特殊用药，图示或序号①②③）与备注（诱导/摆放体位/切皮/拔管等时间与过程）；麻醉小结含**气管导管拔除时间与地点（新增）**；并发症/特殊事件抢救后 **6h 内据实补记**；离室信息含**出室前麻醉后恢复评分 Modified Aldrete（新增，直接回病房/观察室/离院者必填）**；电子病历中麻醉记录部分内容要求同第 6 章（5.9）。（来源：https://www.nhc.gov.cn/fzs/c100048/202408/03a8510913c34f92979e3f290d4a2cbf/files/1733821997274_37256.pdf ；发布公告：https://wjw.fujian.gov.cn/jggk/csxx/jhsyjtfzczcfgc/gzdt_37901/202409/t20240918_6523136.htm ；变化解读：https://zhuanlan.zhihu.com/p/1922932386284413231 ）
3. **手术安全核查制度（十八项医疗质量安全核心制度之一）**：由具有执业资质的**手术医师、麻醉医师、手术室护士三方**，分别在**麻醉实施前、手术开始前、患者离开手术室前**三个时点共同核查——麻醉实施前核对身份/手术方式/知情同意/部位标识/麻醉安全检查/皮肤完整性；手术开始前（Time-out）核对身份/术式/部位并确认风险预警；离室前核对身份/实际术式/术中用药输血/用物清点/标本/皮肤。信息化实践：电子核查单+扫码+语音播报+电子签名+强制流程节点，厦门五院智慧手麻系统使 Time-out 正确执行率由 60% 提升至 91.8%；行业反思亦指出核查流于形式（93% 医院常规执行但质量参差）需信息化硬约束。（来源：http://zgbazwh.org.cn/ListPage/xiangqing?ArticlesID=176 ；https://baike.baidu.com/item/手术安全核查制度/10657609 ；https://www.jdyy.cn/index.php?m=home&c=View&a=index&aid=624 ；https://hlxzz.tjh.com.cn/hlxzz/article/html/20242111 ；https://www.chima.org.cn/Html/News/Articles/8987.html ；https://www.cn-healthcare.com/articlewm/20221027/wap-content-1456574.html ）
4. **手术排班生产实践**：排班调度是手术室"指挥中心"；数字孪生方案将手术资源层归纳为"手术间、人员、设备、器械包、耗材、PACU 和床位"实时资源图，排程预测层基于"术式时长、医生习惯、麻醉方式、患者风险、急诊插台"预测延误与冲突；第一台开台延迟会连锁影响后续接台甚至导致取消排程，"第一台准点开台"是效率管理关键；人卫《手术室管理指南》指出可基于运筹学/组合优化/排序论结合手术台分配方案研发排程系统。（来源：https://www.medicalsystem.com.cn/newsInfo.html/16 ；https://www.aidaoke.com/blog/1783237829180 ；https://zhuanlan.zhihu.com/p/26327074870 ；https://ccdas.pmphai.com/appguide/toPcDetail?sessionId=&knowledgeLibPrefix=guide&id=1915580858622803970 ；https://www.airitilibrary.com/Article/Detail?DocID=16086961-202112-202110080004-202110080004-327-340 ）

6. **术后镇痛（PCA）管理**：《成人术后患者自控镇痛随访专家共识（2025）》确认 PCA 为最常用理想的术后镇痛方法并规范随访；信息化镇痛管理系统覆盖"医嘱、设备使用、疼痛评估、随访、处置记录、质量分析"衔接，电子镇痛记录系统自动采集按压次数/给药量；镇痛达标标准（静息 VAS 0~1 分、镇静 0~1 分、无明显运动阻滞、不良反应轻微）与 APS（急性疼痛服务）查房随访为行业实践。（来源：https://xhyxzz.pumch.cn/article/doi/10.12290/xhyxzz.2025-0340 ；https://rehn.cc/sys-nd/188.html ；https://www.hb3rm.com/view/9015.html ；http://medi-guide.meditool.cn/ymtpdf/0F4A0852-9006-182E-1825-5115BA820731.pdf ）

| 方案 | 说明 | 评估 |
| --- | --- | --- |
| 宽表逐行（每时间栅格一行×全指标列） | 模仿纸质麻醉单，每 1 分钟一行、列=全部监测指标 | WS 329-2024 各指标法定记录粒度不同（脉搏/血压 5min、血氧 15min、呼末二氧化碳 30min，调研依据 2），统一栅格必然产生大量空列；长手术（>5h 须另附页）行数失控；新增监测指标（扩展监测）须改表结构，违背"扩展监测可选"的标准弹性 |
| 全量本地落库（术中从 M14 同步全量遥测到本模块库） | 遥测明细双写一份 | 与 M14 单管道架构（总 Spec D2）冲突；与 iot_telemetry 保留策略（明细 90 天+压缩降采样）形成两套时序账，一致性无权威；存储冗余无业务增益 |
| **监测点流+事件标注流双流合一（选定）** | 麻醉记录单=主档+两类子流：① `anesthesia_monitor_point` 监测数据点流（指标编码引用 M14 术语字典 MDC、测点时间、值、来源[IOT 遥测引用/MANUAL 手工/LAB 血气引用/SNAPSHOT 快照固化]）；② `anesthesia_event` 事件标注流（给药/输液/输血/插管拔管/体位/切皮/特殊事件，按 WS 329"标记+备注"建模，序号①②③）。**术中渲染**：实时拉取 M14 遥测查询接口（`/telemetry/query`，趋势图按记录单粒度渲染；床旁实时波形复用 M14 波形白名单通道 `/telemetry/waveform`，**原始波形不入记录单、不落本模块**，与总 Spec D3 一致）；**定稿固化**：记录单定稿时将窗口内遥测按记录单渲染栅格取值固化为本模块快照点（source=SNAPSHOT），此后只读 | 双流正交：监测数据是"连续量"、事件是"离散量"，WS 329-2024 原文即按"术中监测/标记及备注"两节组织（调研依据 2），双流模型与标准同构；渲染端将两流按时间轴合并绘制（纸质麻醉单"曲线+标记"的数字化还原）；遥测引用+快照固化兼顾"术中轻量、病历永久"——M14 明细仅保 90 天，而麻醉记录单须随病历保存 ≥30 年，定稿快照是唯一能同时满足两者的策略 |

**断网/遥测缺失的手工补录合并规则**（选定）：① 手工补录点（source=MANUAL）为麻醉医师在工作站/断网离线端录入的人工确认值，直接落监测点流；② 同一测点栅格内手工值与遥测值并存时**手工值优先入渲染权威位，遥测值保留为参考值可溯**（对齐 M05 体征双通道"点测优先"既定精神）；③ 遥测断流（消费 `iot.telemetry.anomaly`）在记录单上产生"数据缺失"区间标注并生成补录提醒，由麻醉医师补录或确认"监测无效"（WS 329 允许因设备等原因监测无效不记录，须标注）；④ 血气等术中检验结果经 M07 报告查询接口按结果时间点转成监测点（source=LAB_REF），与设备遥测同轴渲染；⑤ 定稿校验：法定粒度栅格（5/15/30min）缺失点必须逐点被"手工值/监测无效标注"覆盖，否则拦截定稿并提示。

**结论**：双流合一 + 遥测引用实时渲染 + 定稿快照固化 + 手工优先合并规则。麻醉开始/结束时间严格按 WS 329-2024 3.2/3.3 定义（入室监测起、出室移交止），PACU 复苏期监测数据仍挂同一麻醉记录单（phase 标记手术间/复苏室），保证术中与复苏数据连贯一致（调研依据 9）。

### 3.2 手术排程模型：复用 M08 检查号源池 vs 全天单队列 vs 手术室×日期×台次资源池

| 方案 | 说明 | 评估 |
| --- | --- | --- |
| 复用 M08 exam_slot 号源池 | 手术排班套用"设备×时段×容量"检查预约模型 | 语义不合：M08 号源池面向患者流（同设备同时段可多患者），手术是**房间×时间段的独占占用**（一台手术独占手术间直至离室）；接台顺延、急诊插台、台次概念在号源池模型中无处安放；M08 Spec 已明确其模型服务于检查预约，跨模块复用会互相污染语义 |
| 全天单队列（每日每房间一个顺序队列，不设台次） | 排班=向队列追加手术 | 简单但无法表达"上午台/下午台"班次管理、急诊预留台、接台顺序调整；与手术室"台次制"实际运营形态不符（调研依据 4 数字孪生资源层含台次） |
| **手术室×日期×台次资源池（选定）** | `or_schedule`（手术室×日期×台次）持台次属性（类型：择期/急诊预留/急诊插台、计划起止、状态），台次内按顺序持有排程手术；冲突检测=同一手术间时间窗互斥（条件更新+唯一约束，对齐 M08"DB 条件更新防超约、不引入 Redis 预扣"的简单优先口径——手术日量级低，无需高并发抢占用）；时长预估按"术式历史统计×麻醉方式系数×术者习惯"参数化取值；急诊插台=占用预留台或中断当前接台（按急诊级别规则顺延，顺延链留痕）；第一台准点开台监控 | 与手术室真实运营形态一致（台次制+接台+急诊预留）；与 M08 设备×时段模型**风格对齐但独立建模**（同为排他/共享资源池思路，独占语义与独占资源对象不同）；排班量级低（千床位约 20-40 手术间、日均数十台），DB 约束即可保证一致，避免过度设计 |

**结论**：手术室×日期×台次独立资源池。手术间属性（层流级别/专科属性/设备配置）独立于 M01 组织维护；急诊手术插台规则：一级优先占用"急诊预留台"，无预留台时按急诊级别中断当前接台（已过切皮点者待其结束后插入，未切皮者顺延让位），全部顺延联动改期通知（经 M01 通知中心）并留顺延链；手术间维护停用=整日台次冻结+已排手术批量改期。

### 3.3 手术安全核查数字化：提醒式核查 vs 状态机硬门控（三方电子签名+时序强制）

| 方案 | 说明 | 评估 |
| --- | --- | --- |
| 提醒式核查（电子核查单仅做记录，不拦截流程） | 核查单电子化、签名留痕，但手术状态推进不依赖核查完成 | 实现最简，但正是行业反思的核心病灶——"核查流于形式、漏执行无拦截"（调研依据 3：执行率与规范率靠 PDCA 事后追赶）；核查制度的意义（防错误身份/部位/术式手术）在关键时刻（麻醉实施前/切皮前）失效；电子病历评级"业务闭环"要求关键节点强制，提醒式不构成闭环 |
| 全硬门控无例外（三时点核查全部硬拦截） | 任一时点核查未完成一律不得推进 | 对择期手术成立；但急诊抢救场景（心跳骤停即刻剖胸等）硬拦截可能延误救命时机，制度本身允许紧急情况特殊处理，系统必须提供合规的例外通道 |
| **状态机硬门控+急诊例外放行（选定）** | 三时点核查步骤各自为"PENDING → IN_PROGRESS（任一方签名）→ COMPLETED（三方签名齐，经 M01 CA 电子签名）"子状态，并作为手术状态机的**服务端迁移前置条件**：① 麻醉实施前核查 COMPLETED 是 `READY → ANESTHESIA（麻醉开始）` 的硬门控；② 手术开始前 Time-out 核查 COMPLETED 是 `ANESTHESIA → INTRAOP（手术开始/切皮）` 的硬门控；③ 离室前核查 COMPLETED（与清点完成、毒麻借用闭环共同）是离室推进的硬门控；**例外通道**：急诊抢救经"双人授权（麻醉科值班负责人+手术室护士长，独立权限点）+原因强制+例外标记"，步骤置 WAIVED 放行并生成 24h 内事后审查清单（推送医务与麻醉科主任，对齐 M05 破码放行同款治理），例外率作为麻醉质控指标供 M19 | 把"制度要求的三方共同核查"从纸质签名升级为服务端强制时序，未核查物理上无法进入下一阶段（调研依据 3 信息化实践+硬约束趋势）；电子签名留痕满足十八项核心制度追溯要求；例外通道保住急诊时效且全程审计；核查项内容按官方《手术安全核查记录单》三时点条目固化快照，防"签了但没核"的空签——签名时点系统自动校验关键项（身份/部位/术式/知情同意）必须逐项确认而非整单一键签 |

**结论**：状态机硬门控+三方 CA 电子签名+急诊双人授权例外放行+24h 事后审查。三时点条目快照随核查单存档随病历归档。

### 3.4 器械敷料清点模型：文本记录 vs 四时点结构化清点单（双签确认+差异处置+离室锁定）

| 方案 | 说明 | 评估 |
| --- | --- | --- |
| 自由文本记录（护理记录内描述清点结果） | 护士在术中记录里写清点情况 | 无法逐项追溯应到/实点数；差异处置无载体；"未清点完成不得关闭手术"无数据支撑，遗留风险（器械敷料遗留体腔）无系统防线 |
| 单次终末清点（仅手术结束清一次） | 只在缝皮后清点 | 违背人卫指南四次清点时机（开始前/关闭体腔前/关闭体腔后/缝合皮肤后，调研依据 5）；关闭体腔前发现数目不符"立即停止操作查找原因"的纠错窗口（此时体腔未关，尚可寻找）被放弃 |
| **四时点结构化清点单（选定）** | `instrument_count` 与手术 1:1 关联，内含四个时点的清点批次；每批次行项目=器械/敷料/缝针等（物品目录为模块专业字典，器械包引用 CSSD 包标识）+应到数/实点数/完整性质地检查；**双人逐项清点+同步唱点的系统表达=洗手护士与巡回护士双账号分别确认（双签，不得同一人）**；术中添加物品即时入单双人补点；数目不符→批次转差异态：停止关闭体腔相关操作提示→复点→按应急预案处置（查找/X 线/记录上报）→双人+巡回护士记录处置结论后方可继续；**离室锁定：终末清点批次未双签确认或存在未处置差异，手术不得离室推进（硬门控，与核查门控并列）**；RFID/视觉清点设备为预留扩展位不本期实现 | 与清点制度逐条对应；差异态把"停止操作查找原因"固化为系统拦截；离室锁定直接落实"未确认清点完成不能关闭手术"的安全要求；双签分权杜绝单人清点 |

**结论**：四时点结构化清点单+双签确认+差异处置状态+离室锁定。

### 3.5 计费衔接与毒麻借用闭环时序：术毕集中补录 vs 事件驱动计费+扫码即计费、毒麻"借用-给药-退回-核销"四步闭环（对齐 M06/M13 契约）

| 方案 | 说明 | 评估 |
| --- | --- | --- |
| 术毕集中补录计费（手术结束后护士统一录耗材与计费） | 事后一次补录 | 行业实证的漏洞形态——"事后补录"导致漏费/错费且无法与实物勾稽（调研依据 8：扫码即收费正是为杜绝事后补录漏洞）；手术结束时点与耗材使用时点脱节，对账困难 |
| 计费由 M10 自行计价 | 手术模块算好费用写费用表 | 违背总 Spec D5（金额/收费服务端计算，权威在 M13）与 M13 计价唯一权威契约 |
| **事件驱动计费+扫码即计费行登记（选定）** | ① **手术费**：`surgery.surgery.started`（手术开始）事件携带术式↔收费项目对照生成的计费行（主术式+附加操作，item_code+数量+术者/麻醉方式摘要）→ M13 计价（对齐 M13"依赖执行的离散类费用订阅执行域事件即时计费"契约与 M08 登记触发计费同款模式）；② **术中耗材**：巡回护士术中扫 UDI/计费条码→本模块落计费行登记→发布 `surgery.charge-line.registered`（携 item_code+数量+UDI+患者/就诊）→ M13 生成费用（手术间未对接 SPD 智能柜时未用归还以负向计费行冲正，对账经 M13 费用查询 API）；③ **手术结束** `surgery.surgery.finished` 为 M13 耗材计费截止时点与时长类项目计费依据（携带实际时长）；④ 退费前置：M13 退费校验调本模块执行状态查询 API（手术已开始不可退手术费，对齐 M07/M08 执行占用同款契约） | 计费时点锚定执行事件，杜绝"收了费没做手术/做了手术没收费"；扫码计费行与麻醉记录单时间轴可交叉核对（审计）；对照表独立维护使术式变更不改计费逻辑 |

**毒麻借用闭环时序（对齐 M06 Spec 方案 3.3"手术室麻醉用药"分工：借用/退回/核销登记在 M06 专册，麻醉给药记录在 M10，两模块以批号与借用单号互引）**：
1. **借用**：麻醉医师在本模块术前准备界面发起借用申请（手术号+拟用毒麻药品与数量，校验 M01 麻精处方权）→ 调 M06 `POST /api/v1/pharmacy/narcotic-cabinets/{id}/withdrawals` 双人会签取用（麻醉医师+药房双人授权组，M06 专册登记"借用"：批号/数量/双人签名）→ 借用单号回填本模块手术关联台账；
2. **给药**：术中给药经麻醉记录单事件标注记录（药品+批号+剂量+途径+时间+给药人，关联借用单号）——给药事实权威在本模块，不触库存；
3. **退回**：术毕未用部分调 M06 退回入库（专册"退回"登记，实物经双人交接）；
4. **核销**：已用部分凭空安瓿调 M06 `POST /api/v1/pharmacy/ampoule-returns` 空安瓿回收核销（批号/应回收数/实收数/双人签名，M06 勾稽"应回收↔实收"）；
5. **闭环门控**：本模块在手术离室推进时校验该手术全部毒麻借用单已"退回或核销闭环"，未闭环置"毒麻待清"阻断完成（硬门控）；订阅 `pharmacy.narcotic.alerted`（M06 账物差异/核销超时告警）联动提示，差异调查由 M06 状态机承接，本模块只联动展示与阻断。

**结论**：事件驱动计费+扫码计费行+结束截断；毒麻"借用→给药→退回→核销→闭环门控"五步时序。

## 4. 领域模型

表设计统一遵循 README 第 3 节约定：雪花 BIGINT 主键、统一审计字段（created_by/created_at/updated_by/updated_at/deleted）、TIMESTAMPTZ 服务器时间、逻辑删、状态字段 VARCHAR 常量+迁移日志、跨模块引用只存号/code 引用。麻醉方式/手术体位/手术类别/清点物品目录/核查条目模板为本模块专业字典（挂接 M01 字典 code，对齐 M14/M04/M08 先例）。

| 实体 | 关键字段 | 说明 |
| --- | --- | --- |
| or_room 手术室 | room_code、room_name、楼层/区域、层流级别、专科属性（可执行专科集）、设备配置引用（麻醉机/监护仪/腔镜等，引用 M15 资产标识）、每日台次模板（开放时段/台次数/急诊预留台数）、status（启用/停用/维护） | 手术间主数据；维护停用联动整日台次冻结 |

## 5. 状态机与业务流程

- **surgery_apply（围术期主状态机，核查门控硬约束）**：`SUBMITTED（已申请）→ SCHEDULED（已排班，占用台次）→ READY（术前准备就绪）→ ANESTHESIA（麻醉中）→ INTRAOP（手术中）→ RECOVERY（复苏/离室过渡）→ COMPLETED（已完成，终态）`；侧支：`SUBMITTED/SCHEDULED/READY → CANCELLED（取消，终态：患者病情/停嘱/手术间变更，必填原因，联动台次释放与 M04/M13 撤销）`；`ANESTHESIA/INTRAOP → ABORTED（手术中止，终态：必填原因；**中止同样受终末清点完成与离室前核查门控**——体腔关闭前必须完成清点差异处置）`；`RECOVERY → CANCELLED` 不允许（离室后只能走 COMPLETED）。**硬门控迁移条件**（服务端强制，未满足拒绝迁移并留拦截日志）：`READY → ANESTHESIA` 要求"麻醉实施前核查 COMPLETED"；`ANESTHESIA → INTRAOP` 要求"手术开始前 Time-out 核查 COMPLETED"（切皮时点即本次迁移时点）；`INTRAOP/ANESTHESIA → RECOVERY` 要求"离室前核查 COMPLETED + 清点单四批次全部双签确认且无未处置差异 + 毒麻借用单全部闭环"；`RECOVERY → COMPLETED` 要求"Aldrete 出室评分达标（直接回病房者按 WS 329 必填）+ 出室去向登记"。急诊插台产生的新申请以 EMERGENCY 类型直接进入 SCHEDULED（占用预留台/插台）。
- **safety_checklist 步骤**：`PENDING（未开始）→ IN_PROGRESS（任一方已签名）→ COMPLETED（三方签名齐，终态）`；例外：`PENDING/IN_PROGRESS → WAIVED（双人授权例外放行，终态，24h 内事后审查，审查不通过升级上报）`。单据整体状态=三步骤聚合（ANY_PENDING/PARTIAL/ALL_COMPLETED）。
- **anesthesia_record**：`IN_PROGRESS（术中书写中：监测点/事件实时写入，法定栅格缺测待补）→ FINALIZED（定稿：快照固化完成+法定栅格校验通过+麻醉医师 CA 签名，只读）→ ARCHIVED（随病历归档，终态）`；`FINALIZED` 后确需更正走留痕修订版本链（原值可见，对齐 M09 留痕规范与 WS 329 5.8）；定稿时限参数化（默认出室后 24h，超时经 `fy.delay` 提醒麻醉科组长）。
- **instrument_count**：批次状态 `OPEN（批次开启）→ COUNTING（清点中）→ CONFIRMED（双签确认）`；差异侧支：`COUNTING → DISCREPANCY（数目不符，立即提示停止关闭体腔相关操作）→ CONFIRMED（差异处置完成：复点一致/X 线确认/上报记录，双签+处置人留痕）`；全部四批次 CONFIRMED 是离室门控条件。
- **analgesia_order**：`ORDERED（已开单）→ ACTIVE（镇痛中：泵运行，随访计划生效）→ STOPPED（已停用/拔泵）→ COMPLETED（随访完成，终态）`；`ORDERED/ACTIVE → CANCELLED（取消，终态）`；随访逾期经延迟消息提醒 APS 查房（动作式，不改状态）。

主流程时序：

1. **择期手术全链路**：M04 发布 `inpatient.order.audited`（surgery 子键）→ 本模块受理建 surgery_apply（SUBMITTED，发布 `surgery.apply.accepted` 回执供 M04 闭环聚合）→ 排班确认（占用 or_schedule 台次、时长预估、冲突校验、术者手术分级授权强校验[M01 practice/check：三四级逐项]、SCHEDULED，发布 `surgery.apply.scheduled`，经 M01 通知病区/患者）→ 术前管理（访视评估[ASA/BMI/方案]、调 M07/M08 术前检验检查报告、知情同意签署登记、术前准备核查单逐项就绪[素材来自 M05 执行回执]，READY）→ 手术日：入室→麻醉实施前三方核查（电子签名，COMPLETED）→ 麻醉开始（建 anesthesia_record IN_PROGRESS，`READY → ANESTHESIA`，发布 `surgery.surgery.anesthesia-started`）→ 术中（监测点遥测引用实时渲染、事件标注、毒麻给药关联借用单、Time-out 核查 COMPLETED 后 `ANESTHESIA → INTRAOP` 发布 `surgery.surgery.started`[携术式计费行→M13 计价]、术中耗材扫码计费行→M13、四时点清点）→ 术毕（`surgery.surgery.finished` 发布[M09 手术记录 24h 时钟源+首页手术行装配+M13 截断]）→ 离室门控三验（离室前核查 COMPLETED/清点全部 CONFIRMED/毒麻闭环）→ `INTRAOP → RECOVERY` → PACU 复苏（监测数据续挂麻醉记录单 phase=PACU、Aldrete 序列、出室去向登记[病房/ICU]）→ `RECOVERY → COMPLETED`，发布 `surgery.pacu.discharged`（M05 接收回病区/M11 衔接 ICU 转入）与 `surgery.apply.completed`（M04 完成回执、M19 统计）。
2. **急诊插台**：急诊手术申请（急诊级别）→ 无空闲预留台时按规则插台（未切皮接台手术顺延让位，顺延链留痕并通知相关病区）→ 后续链路同流程 1（核查门控不豁免，仅例外放行通道可按双人授权启用）。
3. **麻醉记录单定稿**：出室后麻醉医师补齐栅格缺测（手工补录/监测无效标注）→ 定稿校验（法定栅格覆盖完整/必填段完整[麻醉小结/离室信息/Aldrete]）→ 快照固化（遥测引用点批量转 SNAPSHOT）→ CA 签名 → FINALIZED（发布 `surgery.anesthesia-record.finalized`，M09 引用归档/M19 质控取数）→ 随病历 ARCHIVED。
4. **毒麻借用闭环**：见第 3.5 节五步时序；闭环状态进入离室门控校验集。
5. **术后镇痛与随访**：术毕麻醉医师开镇痛单（配方/参数/泵设备）→ ACTIVE（对接泵设备遥测[经 M14]与随访计划）→ APS 查房随访（VAS/镇静/不良反应记录，不达标调整方案）→ 停用拔泵 STOPPED → 随访完结 COMPLETED；术后随访（24h/72h 并发症随访）结果供 M09 病历与 M19 质控。

## 8. 集成点

- **M01**：认证与 RBAC（申请/排班/核查签名/例外放行/清点双签/定稿/计费行/镇痛开单等独立权限点）；**手术分级授权强校验**（排班确认与手术开始前调 `practice/check`，grant_type=手术分级，三四级逐项授权，对齐《医疗机构手术分级管理办法》调研依据 7；麻醉医师麻精处方权校验经同接口）；字典引用（ICD-9-CM-3 手术操作、麻醉方式等 code，不自建副本）；CA 电子签名（三方核查/清点双签/记录单定稿/知情同意）；通知中心（排班变更/急诊插台/定稿超时/例外审查清单触达）；打印模板（麻醉记录单/核查单/清点单/镇痛单）；审计切面；主数据广播订阅。
- **M02**：一切围术期数据以 `patient_id`+`visit_id` 关联（visit_id 为 M04 签发的 I 型）；患者上下文解析（FROZEN/MERGED 拒绝新建申请）；健康档案身高体重/过敏史供术前评估与 BMI 计算；合并后历史围术期记录读侧经 EMPI 归一。
- **M04（手术医嘱衔接）**：① 消费 `inpatient.order.audited`（surgery 子键）受理建申请，受理/取消/完成经 `surgery.apply.accepted/cancelled/completed` 回执聚合至其闭环追溯（对齐 M04 Spec"M10 受理与完成回执"声明）；② 手术申请语义权威：拟施术式与术前诊断来自医嘱/病历，本模块不改写 M04 医嘱状态；③ 出院联动：`inpatient.visit.discharge-requested` 触发在途手术强制处置提示，出院前手术必须至终态；④ 急诊手术直登的医嘱补关联经其接口登记。
- **M05（术前术后边界，双向对齐其 Spec 第 8 节）**：① 术前准备类任务（备皮/导尿/配血等）归 M05 执行，本模块消费其执行回执做 READY 门控素材；② `surgery.surgery.started` 供其体温单"手术"行与术后天数标注（其 Spec 已声明订阅）；③ `surgery.pacu.discharged`（去向=病房）后患者回到病区护理，术后护理记录归 M05；④ 手术室术中清点与 PACU 复苏记录归本模块（其 Spec 非职责条款一致）；⑤ 术中护理配合记录（巡回护士记录）以本模块核查单/清点单为载体，不在 M05 重复建设。
- **M06（毒麻借用闭环契约，对齐其 Spec 方案 3.3 与第 8 节）**：① 借用：本模块调其 `POST /narcotic-cabinets/{id}/withdrawals` 双人会签取用，借用单号与批号回填手术关联台账；② 给药事实在麻醉记录单（本模块），批号+借用单号互引；③ 退回：术毕未用部分调其退回登记（专册"退回"）；④ 空安瓿核销：调其 `POST /ampoule-returns`，其勾稽"应回收↔实收"；⑤ 订阅 `pharmacy.narcotic.alerted` 联动"毒麻待清"阻断；分工铁律：借用/退回/核销登记权威在其专册，本模块不做任何库存账。
- **M07/M08**：术前检验检查结果、术中血气结果经其报告查询 API 只读引用（血气转监测点 LAB_REF 源）；术前危急值处理以其闭环为准，本模块不重复建设。
- **M09（病历与病案契约，双向对齐其 Spec）**：① 手术事件 `surgery.surgery.started/finished` 为其手术记录文书 24h 时限时钟源（其 qc_rule 时钟源 SURGERY-END）；② 手术结构化信息（实际术式/术者/起止时间/切口等级/愈合/麻醉方式）以本模块 `surgery.surgery.finished` 事件与查询为权威源，其病案首页手术行（homepage_operation）装配引用；③ 手术记录文书（术者书写）归 M09，本模块工作站嵌入其编辑入口；④ 麻醉记录单/核查单/清点单/复苏记录本体在本模块，定稿/归档状态经 `surgery.anesthesia-record.finalized` 与查询供其引用展示与归档联动；⑤ 知情同意文书本体在其，本模块登记签署引用。

- **M13（计费契约，双向对齐其 Spec 第 7/8 节）**：① `surgery.surgery.started`（携术式计费行）→ 其计价；② `surgery.surgery.finished` → 耗材计费截止与时长类计费；③ `surgery.charge-line.registered`（携 UDI 计费行）→ 其生成费用；④ 本模块 `GET /surgery-execution-status` 供其退费前置校验（手术已开始不可退手术费）；⑤ 价格与计价规则权威在其，术式↔收费项目对照在本模块（映射关系非价格副本）；⑥ 计费对账经其费用查询 API。
- **M14（遥测三场景，对齐其 Spec 被依赖声明）**：① 麻醉记录自动采集——按手术时段（麻醉开始至出室）与患者绑定查询设备集，经 `GET /telemetry/query` 拉取监护仪/麻醉机遥测渲染记录单，经 `/telemetry/waveform` 白名单通道展示床旁实时波形（波形不落本模块）；② 断流联动——消费 `iot.telemetry.anomaly` 触发补录提醒；③ 告警透传——术中 `iot.alarm.triggered` 在麻醉工作站与大屏提示；④ 手术开始/结束事件供其标记"手术中"设备使用窗口（与 M15 利用率对账）。

## 9. 非功能与安全

- 性能：排班冲突检测与台次占用 P99 < 100ms（DB 条件更新，日排班量级低）；麻醉事件标注/手工补录 P95 < 500ms；记录单渲染（5h 手术约 20 指标×按栅格折算数千点+事件流）P95 < 1s；定稿快照固化（单台手术全窗口栅格点批量转换）< 30s；大屏刷新 ≤2s（总 Spec 8）；遥测渲染延迟以 M14 查询能力为上界（其最新值 P99 < 100ms 契约）。
- 可用性：手术申请/排班/术中记录 7×24（总 Spec 核心可用性）；M14 不可用时麻醉记录单降级为手工通道（工作站手工录入独立可用，恢复后补采，补录标记）；离线暂存补传（断网不丢术中记录）；M13 不可用时计费行本地暂存补投（outbox 补偿），不阻断手术流程。
- 一致性：状态机迁移与门控校验同事务，迁移留日志；事件发布走 outbox（M20 治理约定），订阅方 eventId 幂等；台次占用条件更新+唯一约束防超占；计费行与 M13 费用每日对账；快照固化与定稿同事务（固化不完整则定稿失败）。
- 审计：核查签名与例外放行（双授权人/原因/审查结论）、清点双签与差异处置、毒麻借用关联、记录单定稿与修订、计费行手工补录、排班变更全量审计（M01 审计切面）；状态迁移日志独立留痕。
- 权限：手术分级授权硬校验（三四级逐项，越级排班/开台拦截并留审计）；三方核查分权（手术医师/麻醉医师/手术室护士三方不得同人互签）；清点双签同人拦截；例外放行双人授权组互斥（对齐 M06 双授权组设计）；数据范围按手术区/科室隔离，跨区查询 403。
- 合规映射：**WS 329-2024《麻醉记录单标准》（强制性标准，2025-08-01 实施）**——记录单内容/粒度/ASA 分级/BMI/体温/呼吸参数/Aldrete/6h 补记/签名与修改规则逐条落地（调研依据 2）；**手术安全核查制度**（三方三时点+电子签名+强制时序，十八项核心制度，调研依据 3）；**《医疗机构手术分级管理办法》**（四级分级/三四级逐项授权/动态管理，调研依据 7）；**《手术物品清点》规范**（四时点双人清点，调研依据 5）；电子病历应用管理规范（修改留痕/时间戳/CA 签名）；麻精药品管理条例（批号追溯/空安瓿核销，经 M06 闭环）；等保三级（审计/TLS/权限最小化/日志脱敏）。
- 数据留存：麻醉记录单/核查单/清点单/知情同意签署随病历保存 ≥30 年；快照固化点长期保留（不参与任何降采样清理）；排班与台次数据在线 ≥3 年后归档；计费行登记与对账记录 ≥3 年；大屏快照数据 ≥1 年。

- 正常：择期手术全链路（受理→排班→访视评估[BMI 服务端计算核对]→知情同意→术前核查就绪→入室→麻醉实施前三方核查→麻醉开始→Time-out 核查→手术开始[M13 计价核对]→术中遥测渲染+事件标注[毒麻给药批号关联借用单]→耗材扫码计费行[M13 费用核对]→四时点清点双签→术毕 finished[M09 时钟/首页素材核对]→离室三验门控→PACU→Aldrete→去向病房[ discharged→M05]/ICU→completed）；麻醉记录单定稿（法定栅格校验→快照固化→CA 签名→只读→M09 引用）；毒麻五步闭环（借用双人会签→给药批号标注→退回→空安瓿核销→门控解除）。

## 12. 与总 Spec 的偏差

无结构性偏差。三处细化澄清（请统一审查裁决确认）：
1. **"5 分钟粒度"监测数据表述**：总 Spec FU-M10-04 与 2.6 节表述为"5 分钟粒度"，本 Spec 按 WS 329-2024（2025-08-01 起实施的现行强制性版本，替代总 Spec 引用的 2011 版原文口径）细化为**分级粒度**：脉搏和血压至少每 5min、血液氧合至少每 15min、呼出气二氧化碳至少每 30min、体温按手术时长要求（>120min 必须监测且至少记录一次）；系统采集按设备原生频率、渲染与定稿校验按上述法定粒度栅格执行。语义为标准版本的时效性更正，非范围变化。
2. **"术前核查单"与"手术安全核查"的关系**：总 Spec FU-M10-02"术前核查单"与 FU-M10-03"手术安全核查"并列，本 Spec 明确：FU-M10-02 的术前核查单=**术前准备核查单**（禁食禁饮/术区准备/配血/饰品去除等，病区与手术室在术前完成）；FU-M10-03=**三方手术安全核查单**（麻醉实施前/手术开始前/离室前三方核查，制度法定口径）。两者实体独立（preop_checklist / safety_checklist）、门控点不同（READY 门控 / 状态机三时点门控）。
3. **FU-M10-06 术后管理优先级**：PACU 复苏记录虽属围术期安全闭环关键环节，但沿用总 Spec 该条目 P2 优先级不调整；其中"离室前核查+清点+毒麻闭环"门控属 FU-M10-03/05/04 的 P1 范围先行实现，PACU 业务单据（pacu_record）随 P2 交付——P2 交付前 RECOVERY 状态以简化过渡形态（去向登记+出室评估）承载，门控语义不变。
