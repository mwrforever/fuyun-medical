## 1. 模块定位与边界

**职责**：本模块是全院药品主数据、药事库存与用药安全闭环的权威中枢，八项职责：① 药品主数据——药品字典及国家医保药品编码对照、基药标识、抗菌药物分级、高警示（高危）药品分级、皮试标识、说明书；② 药库管理——采购入库验收、退库、盘点、批号效期管理、供应商证照管理；③ 药房管理——药库-药房-病区基数点三级调拨、药房库存、基数药管理、退药；④ 处方主数据——门诊/急诊/出院带药处方的权威存储与状态机（住院在院用药以 M04 医嘱为权威源，本模块经关联表衔接）；⑤ 处方前置审核与合理用药监测——规则引擎预检、药师审方工作台、事后全样本处方点评；⑥ 调剂作业——门诊发药闭环（配药→扫码核对→发药签名→退药回收）、住院单剂量摆药、静配中心（PIVAS）审方与贴签对接；⑦ 毒麻精放管理——五专、双人双锁、专用登记账、空安瓿回收核销、批号全程追溯；⑧ 抗菌药物管理与 ADR 上报——分级授权执行、使用强度统计、越级审批、药品不良反应采集与上报。

**非职责**：处方"开立动作"的门诊编排入口与缴费后放行指令（归 M03，本模块提供开方同步 API 与回执事件）；住院医嘱的开立/转抄/执行归 M04/M05（本模块只做用药医嘱的审方、摆药与药品信息供给，不建医嘱表）；资金收退付、药品价格版本与物价项目库（归 M13，药品收费项目及价格权威在 M13，本模块维护药品业务属性与国家编码对照）；给药执行与护理记录（归 M05）；冷链温湿度监控（归 M14/M16，本模块仅订阅超标告警联动批次冻结，P2 预留）；设备资产台账（归 M15）；国标通用字典（ICD 等归 M01，本模块只引用；药品国家医保编码对照属药品业务主数据，权威源在本模块，见方案 3.1）。

**模块红线**：
1. 处方主数据唯一权威源在本模块：处方号由本模块签发，任何模块（含 M03/M04）只登记处方引用与状态回执，禁止复制药品明细作为计费或展示的唯一来源（与 M03 红线 3 对称呼应）；药品计费行由本模块处方事件唯一携带，杜绝处方费用双头生成。
2. 库存以批次账为权威账：一切入库、出库、回补必须落批号与库存流水（只增）；任何出库扣减必须经本模块库存服务完成，其他模块禁止直改库存；汇总余量仅为物化视图，定期与批次账对账。
3. 发药/摆药前置硬校验：门诊处方必须"审方通过 + 已收费（M13 结算完成或绿通挂账，经 M03 放行）"方可配药；住院用药医嘱必须经药师审方通过方可摆药；审方驳回的处方不得进入任何调剂环节。
4. 毒麻精放（麻醉药品、精神药品、医疗用毒性药品）双人双锁、批号级账物一致：单笔取用必须有双人签名与专用登记账记录；空安瓿/废贴未回收核销的处方不得二次调配；登记账与专用处方保存期限按法规执行（麻醉药品处方 ≥3 年，专用账册自药品有效期期满之日起不少于 5 年）。
5. 禁止跨模块读表：执业授权调 M01 API 校验、患者过敏史调 M02 API/事件缓存、价格与收费项目引用 M13 item_code、住院医嘱引用 M04 医嘱号；本模块对外仅暴露 API 与事件。

## 2. 调研依据

1. **处方前置审核生产实践**（北京玛格泰克《我院前置审方系统的建立与实践》，2023）：前置审方改变"开方→缴费→取药→审方"传统流程为"患者交费前完成审核"；规则分自定义审查与系统审查两类，按问题严重程度**提示、拦截或驳回**；处方合格率上线前 97.24% → 上线后 99.56%。（来源：https://manu55.magtech.com.cn/shyy/CN/Y2023/V44/I13/63 ）
2. **前置审方分级与上线策略**：采用"智能处方前置审核软件 + 审方药师"模式，建立审方中心与审方规则库，**先静默运行 2 个月**考察与 HIS 兼容性再分批启用拦截；对不同问题处方分级管理。（来源：http://files.cn-healthcare.com/case/upload/anlidoccms/20220315/46c0d70a-563d-8c6a-451f-24bb2d888243.pdf ；https://www.yydbzz.com/article/2020/1004-0781/1004-0781-39-9-1199.shtml ）
3. **合理用药审查引擎（PASS）**：商用 PASS 引擎覆盖药物相互作用、配伍禁忌、剂量审查等安全用药审查，嵌入开方与审方环节；审方系统由"规则自维护、事前实时审核、事后处方点评"三部分组成，处方点评采用全样本替代抽样。（来源：https://www.medicom.com.cn/ ；https://core.ac.uk/download/pdf/343508756.pdf ）
4. **麻精药品法规**：《医疗机构麻醉药品、第一类精神药品管理规定》（卫医发〔2005〕438 号）要求五专（专人负责、专柜加锁、专用账册、专用处方、专册登记）、专库/专柜**双人双锁**、出入库**双人复核**；患者使用注射剂或贴剂**再次调配时应当要求交回原批号空安瓿或废贴并记录数量**。《麻醉药品和精神药品管理条例》要求专用账册保存期限自药品有效期期满之日起不少于 5 年。（来源：https://www.nhc.gov.cn/bgt/pw10511/200511/17178cd8c3624775857f1ddf9f77efb5.shtml ；https://wjw.hubei.gov.cn/zfxxgk/zc/gfwj/202109/t20210901_3733168.shtml ）
5. **麻精单支赋码追溯**：手术室麻精药品采用院内**单支二次赋码**联合多系统集成实现全流程追溯（取用-使用-空安瓿回收批号级勾稽）。（来源：https://www.yydbzz.com/CN/10.3870/j.issn.1004-0781.2026.09.022 ）
6. **处方管理办法**（卫生部令第 53 号）：处方为**开具当日有效**（特殊情况延长不超过 3 天）；普通/急诊/儿科处方保存 1 年，毒性药品、第二类精神药品处方保存 2 年，麻醉药品和第一类精神药品处方保存 3 年；处方用量限制（普通 ≤7 日、急诊 ≤3 日、麻精注射剂一次常用量等）。（来源：https://www.nhc.gov.cn/yzygj/c100068/200602/890d7c8eb1d64405a060922c93c9f900.shtml ）
7. **抗菌药物分级管理**：《抗菌药物临床应用管理办法》（卫生部令第 84 号）将抗菌药物分为**非限制使用级、限制使用级、特殊使用级**三级；非限制级各级医师均可处方，限制级需主治及以上，特殊使用级经抗菌药物管理工作组指定的专业技术人员**会诊同意**后由具有相应处方权的（高级职称）医师开具；因抢救生命垂危患者等紧急情况可越级使用（**24 小时内补办越级手续**，记录用药指证）。（来源：https://www.moj.gov.cn/pub/sfbgw/flfggz/flfggzbmgz/201207/t20120705_145157.html ；https://www.jlszlyy.com/henzd/11166 ；https://apps.medtrib.cn/media/phone/post/app/2763980/d5c47240-e5fd-40a6-aa34-4597ef7f4b7c.html ）
8. **PIVAS 建设与管理**：国家卫健委《静脉用药调配中心建设与管理指南》（2021）要求静配中心开展医嘱审核干预、加药混合调配；生产流程为"医嘱接收→药师审核→批次划分（排批）→排药→贴签→核对→混合调配→成品核对→分拣配送→退药处理"。（来源：https://www.nhc.gov.cn/wjw/c100175/202112/9bd330edb1a34e5b87cb66d4f657074e.shtml ；http://tg.zhongguoyaoye023.com/download.aspx?action=pdf&id=32751 ；https://zhuanlan.zhihu.com/p/579730258 ）
9. **单剂量摆药与自动摆药机**：包药机接收 HIS 传输的医嘱信息、药师审核后执行单剂量分包摆药（医嘱接收器+摆药机控制系统+分包机三段结构）；单剂量发药制是对中心摆药制的演进，降低差错与污染。（来源：https://yxb.whsjytyy.com/index/view/2022.html ；https://www.gaxrmyy.com/page340.html?article_id=1426 ；http://yxsj.smmu.edu.cn/fileYXSJZZ/journal/article/yxsjzz/2010/1/PDF/20100127.pdf ）
10. **库存批号效期管理**：出库遵循"**先产先出、近期先出、按批号发货**"，效期不足 6 个月不发药（急救除外）；药库调拨出库后**自动生成药房调拨入库单**审核入账；库存预警（安全库存/补货点）、盘点结存为药库系统标配；GSP 要求药品采购记录注明批号/有效期并按批号验收，供应商**首营企业/首营品种**审核与**证照效期预警**为信息化必备。（来源：http://www.huayikangjian.com/detail/12612.html ；https://www.gdhis.net/html/web/xinwenzixun/jishubaike/1864957899420213250.html ；https://www.gxhis.net/615.html ；https://zhuanlan.zhihu.com/p/430724047 ；https://www.sz.gov.cn/zfgb/2013/gb830/content/post_4992293.html ）
11. **病区基数药管理**：抢救车与基数药品由责任护士管理并至少每月全面检查（品种/数量/包装/性状/效期）；三级库系统在基数药到达下限时自动提示药房补发；智能药柜实践提示近效期药品应置外侧张贴"近期"标识优先使用。（来源：https://www.yydbzz.com/CN/10.3870/j.issn.1004-0781.2025.05.004 ；http://china-pharmacy.com/attached/wenjian/14/201708/10163133_3973.pdf ）
12. **高警示药品分级**：高警示（高危）药品按 A/B/C 三级管理，A级须专用药柜/专区贮存、专用袋发放、**双人复核**；HIS 开具医嘱时自动显示高警示药品专用符号提醒医师。（来源：https://www.yydbzz.com/CN/10.3870/j.issn.1004-0781.2025.03.013 ；https://www.hnysfww.com/article.php?id=776 ；http://wap.china-pharmacy.com/attached/wenjian/14/201911/11170107_5473.pdf ）

14. **ADR 监测**：医疗机构是国家药品不良反应报告主体（占全国报告量 86%~90%），经国家药品不良反应监测系统上报；《药品不良反应报告和监测管理办法》按**死亡病例立即、严重病例 15 日内、其他 30 日内**分级时限；CHPS（中国医院药物警戒系统）支持医院内 ADR 智能检索与主动监测（预留扩展位）。（来源：https://www.nmpa.gov.cn/jggk/jgzhn/zhshdw/cdradr/index.html ；https://www.yydbzz.com/CN/10.3870/j.issn.1004-0781.2025.03.009 ；https://www.btch.edu.cn/ksdh/yjb/lcyxk_kswz/ksdt_lcyxk/33355.htm ）

## 3. 方案推导（关键设计点选型）

### 3.1 处方主数据归属与门诊/住院用药统一模型：处方表建 M03 vs 建 M06 且门诊/住院各建一套 vs 建 M06 + 门诊/住院分层模型

| 方案 | 说明 | 评估 |
| --- | --- | --- |
| 处方表建在 M03（门诊开方方） | 处方随就诊模型 | 与 M03 Spec 红线 3"处方引用不复制、不建处方表"直接冲突；审方/调剂/退药/毒麻登记全部需要处方明细权威源，M03 无药学语义；处方还服务于出院带药、互联网处方（非门诊域），放 M03 范围失配 |
| 建 M06 且门诊/住院各建一套独立模型 | 门诊处方表 + 住院医嘱用药表完全独立 | 审方规则、库存扣减、毒麻专册、ADR 关联、药占比统计对两类对象语义完全一致，双套模型导致审方引擎双入口、退药逻辑双实现，必然漂移 |
| **建 M06 + 门诊/住院分层模型（选定）** | `prescription`（处方：门诊/急诊/出院带药/互联网预留）承载**面向患者的独立调剂与缴费单元**；住院在院用药不建处方——`order_medication` 关联表**引用 M04 医嘱号**，与处方共享同一套：药品主数据、审方引擎（review_task）、库存扣减、毒麻登记、ADR 关联 | 处方语义（当日有效、缴费流转、窗口发药）与医嘱语义（长期/临时、转抄执行、频次分解）本质不同，硬统一会让医嘱状态机被处方状态机污染；住院用药权威载体是医嘱（M04，评级 4 级核心），本模块只做"用药审方 + 摆药"的药学切片；出院带药在 M04 是医嘱类型之一，审核通过后转换为 DISCHARGE 类型处方进入门诊同款"缴费→发药"管线（引用医嘱号），两类对象在药学侧收敛 |

**结论与调用时序（对 M03/M13 契约）**：
- **开方走同步 API、状态推进走事件（混合）**。理由：开方是患者在场的同步交互——医生保存处方必须**立即**得到审方预检结果与处方号回执，纯事件异步不满足；而缴费放行、退费逆向等状态推进是跨模块异步链路，事件驱动解耦。
- 时序：① M03 医生站调 `POST /api/v1/pharmacy/prescriptions`（服务端内部先调 M01 `practice/check` 校验处方权/麻精权/抗菌药分级，再执行审方预检，事务内落 prescription 与预检记录，签发处方号）→ 同步返回处方号 + 预检分级结果；② **处方生效（审方通过：预检直过，或药师复审通过）时发布 `pharmacy.prescription.created`**（**载荷携带药品计费行：收费项目 code + 数量 + 用法摘要**）→ M03 登记处方引用（ext_ref）、M13 生成 PENDING 费用——created 事件的语义即"处方开立生效"，硬拦截驳回的处方不发布该事件（发 `pharmacy.prescription.rejected`），从机制上杜绝未审先费；③ 患者缴费 → `billing.settlement.completed` → M03 扇出 `outpatient.order.charged` → 本模块消费后处方转"待调配"并进入药房队列（该通道为门诊/急诊处方的唯一权威放行通道；出院带药 DISCHARGE 处方不经此通道——住院 visit 无该事件，由本模块直接订阅 `billing.settlement.completed`（结算类型=出院结算分支）后转"待调配"，其余调配流程与门诊同款）；④ 调剂完成发布 `pharmacy.dispense.completed` 回流 M03（状态聚合）/M13（执行占用标记）。事件名与 M03 Spec 订阅声明逐一对齐。

### 3.2 审方引擎架构：纯系统实时拦截 vs 纯药师人工审方 vs 规则同步预检 + 药师人工复审两级（分级处置）

| 方案 | 说明 | 评估 |
| --- | --- | --- |
| 纯系统实时拦截（无药师） | 规则命中一律拒绝 | 误报（假阳性）直接阻断诊疗，临床抵触不可持续（前置审方实践均须保留药师人工裁量，调研依据 1、2）；法规上药师是审核第一责任人，不能由规则替代 |
| 纯药师人工审方（无规则引擎） | 全部处方人工过审 | 门诊高峰 2000 人次/h 下药师产能不可行；无规则预检则药师重复劳动、标准不一 |
| **规则同步预检 + 药师人工复审两级、按严重度分级处置（选定）** | 医生保存处方时同步调用预检引擎（毫秒级返回）：**通过级**（无命中，或仅"关注级"提示且医生确认继续）→ 处方即时生效流转；**硬拦截级**（绝对禁忌、致死剂量、明确配伍禁忌、过敏史强阳性、无麻精处方权开麻精等）→ 直接驳回，医生必须修改后重新开立；**提示级**（相互作用、剂量偏大、重复用药、老年人慎用等）→ 生成药师审方任务并实时推送工作台，**药师复审通过前处方不生效、不产生计费与缴费**（落实《处方审核规范》"审核通过后方可进入划价收费与调配环节"）；审方超时经延迟消息提醒升级 | 与生产实践一致（分级"驳回/拦截/提示"+ 静默运行策略，调研依据 1、2）；同步预检保住开方体验，药师只处理机器拿不准的少数处方；**静默运行期**参数化（上线初期提示级降级为"医生确认即放行、任务转事后点评"，按处方类别灰度启用强制复审与硬拦截），支持平滑上线；分级与生效时序与状态机"审方通过（APPROVED）才发 created 事件"严格一致，杜绝未审先费 |

**设计要点**：规则库三层来源——内建规则、商用合理用药规则库（PASS 类，经适配器接入）、医院自定义规则（科室/药品级个性化）；规则分类：配伍禁忌、药物相互作用、剂量/疗程、重复用药（通用名+成分去重）、特殊人群（孕妇/儿童/肝肾功/老年）、过敏史（对接 M02 健康档案）、超说明书、抗菌药分级权限、医保限定支付；预检结果与命中规则解释随处方留档，供药师审方与事后点评复用；审方不通过驳回时附药师意见，回流医生站；同一医生短期内反复被驳回的处方自动升级推送处方点评（联动 FU-M06-08）。

### 3.3 毒麻精放闭环设计：纸质台账电子化 vs 单一登记流水 vs 五专配置 + 双人双锁授权 + 批号级专册账 + 空安瓿回收核销勾稽

| 方案 | 说明 | 评估 |
| --- | --- | --- |
| 纸质台账 + 系统仅记录发药 | 登记账在纸面，HIS 只管处方 | 无法支撑批号追溯与账物实时勾稽；月度检查靠手工，差错发现滞后；不满足"麻精全程可追溯"监管趋势 |
| 单一登记流水表（只记出库） | 电子流水替代专册 | 缺少双人签名、交接结存、空安瓿回收等专册必备要素，审计与药监检查口径不匹配 |
| **五专配置 + 双人双锁授权 + 批号级专册账 + 空安瓿回收核销勾稽（选定）** | ① 五专对象化：专库/专柜（挂责任人、双人授权组、基数）、专用账册（入库/出库/结存专账）、专册登记（批号级笔笔流水）、专用处方（麻精专用处方类型，红处方）、专人负责（授权组管理）；② 每笔取用/发药强制**双人签名**（调剂药师 + 核对药师双账号会签，对应双人复核与双人双锁）；③ 全链条批号追溯：入库批号 → 药库 → 药房/手术室借用 → 处方/医嘱患者使用 → 空安瓿/废贴回收 → 报残销毁，每环节记批号 + 经手人 + 单据引用（调研依据 5 的单支赋码思路以批号 + 追溯码承载）；④ **空安瓿回收核销**：按法规"再次调配时交回原批号空安瓿并记录"（调研依据 4）建模为"应回收数 ↔ 实收数"勾稽——该患者该批号上一次用量未核销时，本处方拦截二次调配（急诊抢救经授权放行并登记）；⑤ **日清月结**：每日结存双人核对（账面 = 实物盘点），差异立即生成差异调查单上报；⑥ 保存期限：麻醉/一类精神处方 ≥3 年、毒性/二类精神处方 ≥2 年、专用账册自效期期满 ≥5 年（调研依据 4、6） | 与法规条款逐条对应可过药监检查；双人会签把"双人双锁"从物理锁提升为系统强制；批号级勾稽使"流入非法渠道"风险可在当日发现 |

**状态机**：毒麻专册账为"笔笔账 + 期初/期末结存"模型，每日日结（DAILY_SETTLED）、每月月结（MONTHLY_CLOSED）；差异调查单独立状态机（见第 5 节）。手术室麻醉用药：M10 麻醉医生经**借用登记**领用（双人签名）→ 术后凭空安瓿与处方核对销账，未用退回入库——与 M10 的分工：借用/退回/核销登记在本模块专册，麻醉给药记录在 M10。

### 3.4 库存账物模型：汇总账 vs 纯批次账 vs 批次账权威 + 汇总物化 + 先产先出近效期先出选批

| 方案 | 说明 | 评估 |
| --- | --- | --- |
| 汇总账（药库/药房两级数量汇总） | 简单直观 | 无法支撑批号追溯、效期管理、毒麻专册与药品追溯码核验；批次信息散落单据中不可聚合；医保追溯码"一次销售一次扫码"核验无处落点 |
| 纯批次账（只记批次） | 批次即账 | 汇总余量、效期分布、库存下限预警每次聚合计算，高峰查询昂贵；货位/冻结等管理维度无处挂接 |
| **批次账权威 + 汇总物化 + 出库自动选批（选定）** | `drug_batch`（库房 × 药品 × 批号）为权威账（数量、货位、锁定数、状态）；`stock_ledger` 只增流水（动作 × 批次 × 数量 × 单据 × 经手人）；库房汇总余量为可重建物化视图（定期与批次账对账，差异告警）；出库由系统按"**先产先出、近效期先出、按批号发货**"自动预分配批次（调研依据 10），配药占用以锁定数表达，未发释放；效期三级预警（参数化：≥6 个月提醒、3~6 个月预警停采优先出库、<3 个月停采停发（急救除外）、过期自动冻结转待销毁）；盘点按"账面/实盘/差异"生成盘点差异单，**差异经审批后以调整流水修正批次账**并全量留痕，禁止直改库存 | 兼顾追溯合规与查询性能；选批策略自动化减少人为错发；效期预警与库存下限预警统一汇入 `pharmacy.stock.alerted` 事件（Fu-M06-02/03 共用）；盘点差异审批链对齐"金额相关操作留痕审批"的等保与财务要求 |

**三级库模型**：药库（一级）→ 药房（二级）→ 病区基数点/抢救车/手术室基数柜（三级）；调拨单跨级流转（出库方发出即锁定，收货方确认入账——出库单自动生成对方入库单待确认，调研依据 10）；基数药按"基数上下限"管理：消耗致下限自动生成补药提醒（经 M01 通知药房），月检提醒（责任护士，调研依据 11）。

### 3.5 计费衔接与退药退费时序：发药后计费 vs 处方事件计费 + 结算放行 + 先退药后退费（对齐 M13 契约）

| 方案 | 说明 | 评估 |
| --- | --- | --- |
| 发药后计费（后计费单轨） | 发药才生成费用 | 与 M13 Spec 已定稿契约冲突（M13 已将"门诊处方事件计费 + 发药为执行占用标记"写入方案 3.1）；门诊患者必须先缴费再取药，发药计费无法成立 |
| 退费与退药并行（无序） | 退钱退药各走各的 | 已发药费用直接退钱会造成"钱退了药没收回"或"药收回钱没退"，资金与实物风险双高（M13 方案 3.3 已将"已发药先退药"定为执行占用硬前置） |
| **处方事件计费 + 结算放行 + 先退药后退费（选定）** | ① 计费行由 `pharmacy.prescription.created` 唯一携带 → M13 生成 PENDING 费用并冻结价格快照（价格权威在 M13，本模块不存价格版本）；② 发药放行条件 = 审方通过 ∧ `outpatient.order.charged`（M03 消费 `billing.settlement.completed` 后扇出，含绿通挂账场景；限门诊/急诊处方，出院带药处方放行条件为 `billing.settlement.completed` 出院结算分支）；③ 退药**实物先行**：药房窗口受理退药（核验药品实物与追溯码，防回流药混入，调研依据 13）→ 批次回补 → 发布 `pharmacy.dispense.returned` → M13 解除执行占用并走退费审批 → `billing.refund.approved` → 本模块处方置"已退药"终态；④ 本模块提供执行占用查询 API 供 M13 退费前置校验调用（已发药未退药受理 → 拦截退费并提示先到药房退药） | 与 M13 Spec 方案 3.3"执行占用硬前置：已发药先退药（M06）"及 M03 Spec FU-M03-08"退药回收归 M06"完全对齐；实物与资金时序单向（先退药后退费），无双头风险；追溯码核验把"退回药品确属本院发放"变成系统强制（对齐《中国药房》门诊药房追溯闭环实践） |

| narcotic_discrepancy 毒麻差异调查单 | 品类/批号、账面数/实物数/差异数、发现环节（日结/月结/抽盘）、双人核查记录、结论（补账/报批/上报）、状态 | 日结差异自动生成；OPEN 期间对应批号冻结禁止发放 |

| adr_report 药品不良反应报告 | patient_id、关联处方/医嘱/批号、反应描述、发生时间、严重程度（一般/严重/死亡）、时限类别、报告人、药学部审核意见、国家系统上报凭证引用、状态 | FU-M06-10；批号级关联支撑上市后风险追溯 |

## 5. 状态机与业务流程

- **prescription**：`CREATED(已开立：提示级待药师复审；硬拦截经本状态转 REJECTED) → APPROVED(审方通过/放行，生效并发 created 事件) → PENDING_FEE(待缴费，由 billing.fee.created 驱动迁移，M13 PENDING 费用已生成) → PENDING_DISPENSE(已缴费待调配：门诊/急诊处方消费 outpatient.order.charged，出院带药 DISCHARGE 消费 billing.settlement.completed 出院结算分支) → DISPENSING(配药中，批次锁定) → DISPENSED(已发药，终态基点) → PART_RETURNED / FULL_RETURNED(已退药，billing.refund.approved 后终态)`；`CREATED → REJECTED(审方驳回，必附药师意见，可修改后重新开立新版本)`；`APPROVED/PENDING_FEE → CANCELLED(作废，未缴费，联动 M13 费用作废与 M03 引用状态)`；`PENDING_DISPENSE/DISPENSING → CANCELLED(已缴费未发药作废/退费：必填原因，联动 M13 退费/费用作废与 M03 引用状态收敛，并释放 dispense 锁定批次)`。预检通过级的处方 CREATED 与 APPROVED 同步完成（同事务）；提示级处方在复审通过前停留在 CREATED，不产生计费。`REJECTED/CANCELLED` 为终态；`DISPENSED` 后原处方只读，退药生成退药单关联。部分退两类时点口径：① 发药完成后部分退——处方转 PART_RETURNED，剩余明细已随原发药全部发出，不存在再发药；② 发药中部分明细退场——dispense 明细级取消（释放锁定批次），处方保持 DISPENSING 直至剩余明细调配发药完成。预留（P2）：rx_type=INTERNET 外配处方终态 `FLOWED_EXTERNAL`，由 M18 流转回执事件驱动（事件名 P2 登记）；外配场景"费用作废≠处方作废"——院内 PENDING 费用作废时处方转 FLOWED_EXTERNAL 而非 CANCELLED。
- **review_task**：`PENDING(待审，实时推送工作台) → IN_REVIEW(药师接单) → APPROVED / REJECTED(必附意见)`；超时未审经延迟消息提醒组长并升级（不自动处置）。预检自动通过的任务直接落 `APPROVED(处置者=系统)`。
- **dispense（门诊发药）**：`CREATED(放行入队) → PICKING(配药中，批次锁定+追溯码采集) → PICKED(已配药待核对) → ISSUED(发药签名完成，发布 pharmacy.dispense.completed，终态基点) → PART_RETURNED / FULL_RETURNED(退药完成)`；`CREATED/PICKING → CANCELLED(处方作废联动，释放锁定批次)`。发药中部分明细退场为明细级取消（释放对应锁定批次），单据保持 PICKING 继续剩余明细；整单 CANCELLED 时释放全部锁定批次。
- **dispense（住院摆药）**：`CREATED(按医嘱生成摆药计划) → PICKING(摆药/包药机执行) → PICKED(药师核对) → CHECKED(核对完成出库交接，PIVAS 成品核对通过) → DELIVERED(病区签收完成，发布 pharmacy.dispense.completed)`；退药（病区退回，停嘱/出院联动）：`DELIVERED → PART_RETURNED / FULL_RETURNED`。
- **transfer_order**：`REQUESTED → OUT_BOUND(出库确认，批次锁定) → RECEIVED(入库确认，批次入账，终态)`；`REQUESTED → CANCELLED`。
- **stocktake**：`DRAFT → COUNTING(盘点中) → PENDING_APPROVAL(差异待审) → ADJUSTED(审批通过，调整流水入账，终态)`；`PENDING_APPROVAL → REJECTED(驳回重盘)`。
- **narcotic_discrepancy 差异调查单**：`OPEN(差异发现) → INVESTIGATING(双人核查中) → RESOLVED(结论+补账/报批) / REPORTED(上报药监与公安，法规要求)`；`OPEN` 期间对应批号禁止二次发放。
- **antibio_approval**：`DRAFT → PENDING_CONSULT(特殊级待会诊) → APPROVED(会诊同意/越级审批通过) / REJECTED`；越级使用 `APPROVED` 后 24h 内未补办手续自动置 `EXPIRED_ILLEGAL` 并通报医务与抗菌药物管理组。
- **adr_report**：`DRAFT(填报) → SUBMITTED(院内提交) → VALIDATED(药学部审核修正) → REPORTED(国家监测系统上报成功，留回执) → FEEDBACK(随访/再评价)`；时限到期未上报经延迟消息升级（死亡立即、严重 15 日内、其他 30 日内）。

主流程时序：

1. **门诊开方→缴费→发药闭环**：医生站（M03）调开方 API → M01 执业授权校验 + M06 审方预检（同步，返回处方号与分级结果）→ 预检放行（或药师复审通过）发布 `pharmacy.prescription.created`（携计费行）→ M03 登记引用、M13 生成 PENDING 费用 → 患者缴费（M13）→ `billing.settlement.completed` → M03 扇出 `outpatient.order.charged` → 本模块处方转 PENDING_DISPENSE 入药房队列 → 配药（系统按近效期先出预分配批次并锁定，逐码采集追溯码）→ 扫码核对（处方条码 + 药品追溯码 + 患者取药凭证）→ 发药双签 → `pharmacy.dispense.completed` → M03 状态聚合（待取药解除）/M13 执行占用标记。
2. **退药退费**：患者到药房申请退药 → 药师核验实物（外观/批号/追溯码与发药记录一致）→ 生成退药单（批次回补 + 流水）→ 发布 `pharmacy.dispense.returned` → M13 解除执行占用、走退费审批 → `billing.refund.approved` → 本模块处方/发药单置已退药终态；M13 退费前置校验调用本模块占用查询 API，已发药未退药受理的退费申请被拦截并提示先退药。
3. **住院医嘱用药审方与摆药**：M04 医嘱开立（用药类）→ M04 发布医嘱审核事件 → 本模块审方预检（提示级生成审方任务，药师通过前不摆药）→ 药师审核结论发布 `pharmacy.medication-order.audit-completed` / `pharmacy.medication-order.audit-rejected` 回流 M04（载荷 target=m04_order_no，驱动医嘱 AUDITED 迁移；rejected 必附药师意见回流医生站改方）→ 通过后进入摆药计划 → 单剂量摆药（包药机对接：医嘱数据下发/结果回传）或 PIVAS 调配（审方→排批→贴签→核对→配送）→ 病区签收 → `pharmacy.dispense.completed` → M13（占用）/M05（摆药到病区供给药核对）；停嘱/出院联动：停嘱事件 → 未摆药计划作废，已摆药未用部分走病区退药回补。
4. **毒麻取用与核销**：处方（麻精专用类别）审方通过 → 药房双人会签取用（专册登记：批号/数量/双人签名）→ 发药时核验上次空安瓿回收核销（未核销拦截，急诊授权放行登记）→ 发药登记专册 → 患者下次取药时交回空安瓿（批号核对）→ 核销勾稽；每日日结双人核对账物，差异转调查单并冻结批号。
5. **审方队列实时处置**：预检发现提示级问题 → 生成 review_task 并实时推送审方工作台（WebSocket）→ 药师对照患者健康档案（过敏史来自 M02 订阅缓存）与历史用药 → 通过（处方生效流转）/驳回（附意见，M03 医生站收到 `pharmacy.prescription.rejected` 提醒）→ 超时未审经延迟消息升级。

| FU-M06-08 合理用药监测（P1） | 与 FU-M06-07 共用审方引擎与规则库（同一引擎两个部署场景：事前预检嵌入 M03/M04 开方界面实时提示；审方工作台完整规则命中展示）；规则库来源适配器：内建规则 + 商用 PASS 类规则库接入位 + 自定义规则；事后处方点评：全样本批量复审（引擎初筛 + 药师/医师专家组点评双签），不合理处方按"不规范/用药不适宜/超常"三大类分类统计（调研依据 16），点评结果关联医生与科室，回流规则库优化并供 M19 质量指标取数 |
| FU-M06-09 抗菌药物管理（P1） | 抗菌药分级目录在药品字典维护（分级变更走药事管理与抗菌药物管理工作组审核流）；开方/医嘱开立时强校验 M01 执业授权（非限制：有处方权医师；限制：主治及以上；特殊：高级职称 + 会诊同意，调研依据 7）；越级使用：紧急情况限 1 日用量、24h 内补办越级手续（antibio_approval 状态机超时升级并通报医务）；使用强度统计：DDD 值维护于药品字典，按"抗菌药物消耗量（累计 DDD 数）/同期收治患者人天数 ×100"计算使用强度（AUD），门诊抗菌药物处方比例、住院使用率等指标统计（对齐抗菌药物专项整治目标口径），供 M19 与抗菌药物管理组取数；处方点评与抗菌药专项点评联动 |
| FU-M06-10 药品不良反应上报（P2） | 采集：医护/药师填报（患者/药品/批号/反应描述/处置/转归，关联处方或医嘱引用）；药学部审核修正（VALIDATED）；上报：按《药品不良反应报告和监测管理办法》时限分级（死亡立即、严重 15 日内、其他 30 日内，调研依据 14），经国家药品不良反应监测系统上报——对接方式预留两种：系统直连接口位（经 M20 通道）与规范报表导出人工上报；上报回执留痕；批号级关联支持上市后风险召回排查；主动监测（CHPS 类智能检索）为扩展预留位不提前实现；严重 ADR 自动提醒关联药品近期用药患者清单（院内排查辅助） |

## 8. 集成点

- **M01**：认证与 RBAC（审方/调剂/毒麻双锁/盘点审批/调价联动/ADR 上报等独立权限点）；执业授权强校验（开方 API 内部调 `POST /api/v1/system/practice/check`：处方权/麻精处方权/抗菌药三级，与 M03 开方入口校验构成纵深防御）；字典引用（给药途径/频次/诊断 code，不自建副本）；系统参数（效期预警阈值、静默运行开关、审方超时阈值等）；通知中心与打印模板（瓶签/摆药单/毒麻专册报表）；审计切面；订阅主数据广播刷新缓存。
- **M02**：一切处方/医嘱用药/ADR 以 `patient_id` 关联；审方预检嵌查过敏项快速校验 API（M02 内部服务接口）+ `patient.health-summary.updated` 订阅双通道；患者合并后历史处方读侧经 EMPI 归一。
- **M03（处方与发药边界契约，双向对齐其 Spec）**：① 开方：M03 医生站调本模块开方同步 API（开立动作入口在 M03，处方主数据在本模块，M03 红线 3"处方引用不复制"由本模块红线 1 对称保障）；② 计费行：`pharmacy.prescription.created` 携带（M03 澄清 3 的落地方）；③ 放行：消费 `outpatient.order.charged` 进入调配；④ 回执：`pharmacy.dispense.completed/returned` 供 M03 visit 状态聚合；⑤ 退药时序收敛：已发药退费的**实物退药先行**（本模块药房窗口受理，对齐 M13"已发药先退药"硬前置），`outpatient.order.cancelled` 在本模块承担**终态确认**职责（未发药处方作废 / 已退药单据终态，不再承担退药指令），两模块与 M13 三方时序以"退药受理 → 退费审批 → 终态收敛"单向链为准（统一审查 B-3 已裁决落定）；调剂作业实体与界面归本模块（M03 不建调剂表）。
- **M13（计费与退费契约）**：药品收费项目与价格权威在 M13（本模块 drug 以 item_code 关联、不存价格版本）；药品国家医保编码对照权威在本模块（M13 引用）；PENDING 费用由本模块处方事件驱动生成，本模块订阅 `billing.fee.created` 驱动处方 APPROVED → PENDING_FEE 迁移；出院带药放行订阅 `billing.settlement.completed`（结算类型=出院结算分支）；执行占用查询 API 供退费前置校验；退药退费严格"先退药（本模块）后退费（M13）"；住院摆药完成事件供 M13 执行占用标记。
- **M04（住院用药衔接）**：住院在院用药权威载体为 M04 医嘱，本模块经 order_medication 引用（不建医嘱表、不复制医嘱内容）；订阅 M04 医嘱审核/变更/停止事件驱动审方与摆药；出院带药医嘱审核通过后由 M04 调本模块开方 API 生成 DISCHARGE 处方（引用医嘱号）进入同款调配管线（放行不经 `outpatient.order.charged`，由本模块订阅 `billing.settlement.completed` 出院结算分支驱动转 PENDING_DISPENSE，见方案 3.1）；本模块审方驳回意见回流 M04 医生站。
- **M05（摆药-给药衔接）**：摆药单病区签收后 M05 获得摆药结果（`pharmacy.dispense.completed` 订阅）供其给药任务核对；M05 PDA 给药核对经本模块药品查询 API 获取药品主数据/批次效期/高警示标识；病区退药由 M05 发起、本模块受理回补；具体事件名衔接以 M05 Spec 登记为准。
- **M09**：处方、发药/摆药记录、ADR 报告作为患者全景用药域数据源（经取数 API，只读）。
- **M10**：手术室麻醉用药借用/退回/空安瓿核销在本模块毒麻专册登记（双人签名），麻醉给药记录在 M10，两模块以批号与借用单号互引。
- **M18（P2 预留）**：互联网处方经 rx_type=INTERNET 复用审方引擎与处方模型（处方流转对外接口预留位，本期不实现）；预留外配终态 `FLOWED_EXTERNAL`（由 M18 流转回执事件驱动，事件名 P2 登记），并约定"费用作废≠处方作废"——外配场景院内 PENDING 费用作废时处方转 FLOWED_EXTERNAL 而非 CANCELLED。
- **M19**：药占比、抗菌药使用强度/使用率、处方合格率、ADR 报告率等统计取数 API（只读）。
- **M20**：事件信封/交换机/队列治理、幂等构件、延迟队列（审方超时 `delay.review-timeout`、空安瓿回收核销超时 `delay.ampoule-return`、月检提醒 `delay.base-stock-monthly`）、出站通道（国家 ADR 监测系统直连预留、自动摆药机接口经适配器）；本模块全部事件先登记 event_registry。
- **M14/M16（P2 预留）**：药品/疫苗冷链温湿度超标告警订阅位（事件名以 M14/M16 Spec 为准），联动受影响批次冻结，本期不实现。

## 9. 非功能与安全

- 性能：开方同步 API（含 M01 授权校验 + 审方预检）P95 < 500ms（预检引擎单处方 P99 < 100ms，规则集内存缓存）；门诊发药高峰（按 2000 人次/h × 平均 1.5 张处方规划）批次扣减以行级条件更新 + 锁定数表达，P95 < 200ms；审方任务 WebSocket 推送端到端 ≤ 1s；库存汇总查询走物化视图；摆药计划夜间批量生成（长期医嘱日切分解后错峰执行）。
- 可用性：门诊发药/住院摆药 7×24（总 Spec 核心可用性）；审方预检服务不可用时按参数降级：急诊/绿通处方放行并标记"待补审"（审方恢复后补审，不通过拦截在途未发药处方），非急诊处方进入待审队列暂不流转；摆药机不可用降级人工摆药（计划不变）。
- 一致性：批次扣减与流水同事务；事件发布走 outbox（M20 治理约定）；汇总账与批次账每日对账、差异告警；毒麻专册与批次账日清月结强制勾稽；`pharmacy.prescription.created` 与处方生效同事务落 outbox，杜绝"处方生效但计费事件丢失"。
- 审计：毒麻全操作（取用/发放/回收/销毁/差异处置）、审方通过/驳回、处方作废、盘点调整、供应商证照变更、ADR 上报全量审计（M01 审计切面）；处方与医嘱用药的药师签名（调配/核对双签）为法定留痕，不可篡改。
- 权限：药师审方权限、调配/核对分权（同一处方不得同一人双签）、毒麻双人授权组互斥（同一人不得同时在两个授权组）、盘点审批分权、ADR 上报权限分设；数据范围按库房/药房隔离。

## 12. 与总 Spec 的偏差

无偏差。四处细化澄清（已经统一审查裁决确认：全部采纳）：
1. **处方主数据归属**：总 Spec M03 条目 FU-M03-06"处方（调 M06）"与 M03 Spec 红线 3 已隐含处方主数据在 M06，本 Spec 明确为正式结论（方案 3.1）：`prescription` 表在本模块 schema，M03 仅登记引用；事件名 `pharmacy.prescription.created` 与 M03 Spec 订阅声明逐一对应。
2. **住院用药不建处方**：住院在院用药以 M04 医嘱为权威源、经 order_medication 引用衔接审方与摆药，仅出院带药转换为 DISCHARGE 处方；总 Spec FU-M06-05"住院摆药"条目按此口径细化。
3. **"五专"表述**：总 Spec FU-M06-06 写"五专（专人/专柜/专锁/专账/专册）"，本 Spec 按法规完整口径细化落对象（专人负责、专柜加锁+双人双锁、专用账册、专用处方、专册登记，另含空安瓿回收与批号追溯），语义一致、覆盖更全。
4. **FU-M06-07 与 FU-M06-08 共用引擎**：前置审核与合理用药监测共用同一审方规则引擎与规则库（两个部署场景：事前预检/事后点评），避免双引擎漂移；两 FU 条目均完整落地。
